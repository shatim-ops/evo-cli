# Состояние роли «Процесс и тестирование»

Файл состояния роли (`CLAUDE.md` §0, правило 5). Новая сессия роли читает его
после `release-plan.md`, последнего `handoff/<версия>.md`, `DECISIONS.md` и
`RELEASING.md`. Обновляет сессия роли при каждом заметном изменении и перед
закрытием. Одна страница, без внутренних сведений Cloud.ru.

Роль: как мы проверяем, что evo не сломан. Тестовая инфраструктура, CI и
workflows, аудиты процессов, брифы Cursor и Grok, проверка цепочки поставки
на rc, падения CI не от diff. Продуктовый код не меняет: дефект продукта —
падающий тест и диагноз для «N — разработки».

Роль сквозная, сессия — на версию («Процесс · N», `CLAUDE.md` §0, правило
5): перед закрытием сессия обновляет этот файл, следующая начинает с него и
берёт задачи из бэклога, а не по памяти.

Обновлено: 23.10.2026 (сессия «Процесс — разработка», последняя до
«Процесс · 1.3»).

## Открыто

- **6.4 на `1.3.0-rc.1`.** Проверить по `docs/RELEASING.md`: SBOM у каждого
  архива в подписанном `checksums.txt`, `gh attestation verify` на архивах,
  `cosign verify` образа по digest. Риск: реестр образов может не принять
  подпись cosign — тогда решение владельца, где хранить подпись. Нужно
  одобрение rc в окружении `release`.
- **Атака Grok** по `docs/internal/briefs/grok-attack-1.3.md`: каждую
  находку закрепить тестом в репозитории (`CLAUDE.md` §5).
- **Этап 5** — проверка первой волны отдельной сессией Fable (открывает
  владелец).
- **Этап 7 (1.4)** — нагрузочный тест на фейке, бенчмарки перед minor,
  потолок стоимости как инвариант (`process-1.2.1-stages.md`).
- **CI не от diff: падение рантайма Go на Windows под `-race`.**
  `0xc0000005` в `adjustdefers` при `shrinkstack` во время сборки мусора, в
  `internal/tools`. Было дважды: #226 (22.10) и #219 (23.10, PR без
  `.go`-файлов); оба раза другие ОС зелёные. Гипотеза, не проверена:
  golang/go#79249 — асинхронное вытеснение на Windows ломает поток внутри
  обработки исключения; исправление — к Go 1.28, в 1.26.10 его нет. План:
  третий случай — PR «(процесс)» с `GODEBUG=asyncpreemptoff=1` только в
  шаге тестов на Windows, комментарий со ссылкой на issue, решение
  владельца; убрать, когда CI перейдёт на версию Go с исправлением.
- **CI не от diff: `startup_failure` у повторного запуска** (#219, run
  39917297878, попытка 2: ни одного job, логов нет). Повтор работал 22.10
  (run 39832726395); с тех пор в `ci.yml` — job `classify` (#208), связь не
  доказана. Проверка: один «re-run all jobs» на PR этой роли. Тоже
  `startup_failure` — разбирать `ci.yml`, это касается каждого PR.

## Инструменты

- **Миры** (`internal/cli`): `withParityWorld` (превью, считает записи),
  `withJSONWorld` (ответы, S3, kubectl/helm), мир двойников (#236);
  `TestParityWorlds_NoProductionWaits` держит все ожидания мира в
  миллисекундах.
- **Матрица сбоев** (`internal/tools/fault_*_test.go`): новый изменяющий
  инструмент — случай `apiCase`/`computeCase` или строка `faultMatrixOut` с
  причиной, иначе падает `TestFault_MatrixCoversTheRegistry`. Фейк отказов —
  один файл в `engine` и `tools` (`TestFaultFakeCopiesMatch`).
- **Правила тестов:** `internal/testrules` (часы стенки), `internal/clock`,
  `internal/workflows` (правила workflow).
- **Слияние CHANGELOG при вливании `main`:** раздел `[Не выпущено]` —
  из `main` плюс пункты, которые ветка добавила к общей базе (`git
  merge-base`); после — сверить, что ветка добавляет к `main` ровно свои
  пункты и ничего не теряет. Двустороннее слияние задваивает пункт, который
  `main` переписал.
