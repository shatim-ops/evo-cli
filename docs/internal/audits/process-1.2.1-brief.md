## Цикл одного PR (учтён в оценках ниже)

Каждый PR проходит полный цикл §4 `CLAUDE.md`, не только написание кода:

1. тест, падающий без правки → gofmt, vet, staticcheck, `go test -race` локально;
2. PR → ревью Qwen: до PR 2 запускает владелец комментарием `/qwen review`,
   после PR 2 — автоматически при открытии; 5–15 мин ожидания;
3. разбор каждой находки Qwen в ответном комментарии: исправлено или
   опровергнуто с обоснованием; при исправлении — повторный push и CI;
4. CI на трёх ОС (10 мин до PR 1, 2–3 мин после);
5. squash-merge по полному SHA — релизная сессия.

Цена цикла сверх кода: 20–40 мин Claude на PR (ожидание Qwen и разбор),
один комментарий владельца на PR до автоматизации. Поэтому автозапуск Qwen
идёт вторым PR, а не седьмым: он убирает ручной шаг у восьми следующих.

## Кто делает

По умолчанию всё делает сессия Claude. Ревью Qwen — обязательная часть
цикла каждого PR. Cursor и Grok — необязательны: задача им ставится брифом,
если владелец решит разгрузить сессию или захочет независимый взгляд; та же
задача без брифа выполняется в сессии Claude.

| Что | Подходит для брифа | Почему |
|---|---|---|
| PR 6 (документы процесса), PR 7 (`actionlint`, `deadcode`), PR 10 (еженедельный `-race -count=3 -shuffle`) | Cursor | самостоятельные задачи с ясным критерием приёмки, без контекста фейков и реестра |
| Проверка «документация против бинаря» после PR 6 | Cursor | независимый взгляд на документы, бриф 2А уже есть |
| Атака на новые поверхности: вынос ключа наблюдателя из `cloud-readonly` workflow'ом с ветки `claude/*` (после В3 и PR 9); подмена классов через пути (после PR 8); наборы инструментов и режим без удалений (перед 1.3) | Grok | это поверхности, которые первая волна создаёт; чёрный ящик ценнее собственной проверки |
| PR 1, 3, 4, 5, 8, 9; вторая волна | только Claude | правки тестов и движка, нужен контекст фейков, реестра, инвариантов; PR 9 трогает живое облако |

Если бриф выдан: находки Qwen по PR Cursor разбирает Cursor в том же PR;
находки Grok — issue с меткой `безопасность`, разбирает Claude. Без брифа
те же проверки (в том числе атаку на `cloud-readonly`) делает сессия Claude
как тесты и отдельный PR.
