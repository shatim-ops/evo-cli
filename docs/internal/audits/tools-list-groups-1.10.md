# Размер групп инструментов в tools/list — замер к 1.10 (17.11.2026)

Строка плана «Кандидат 1.10 — размер групп инструментов для агента»
(поручение владельца 17.11), пункт (1) — замер. Хозяин — «Процесс». Пункты
(2) — порог на группу в CI — и (3) — вынос групп — идут по этому замеру
отдельными строками.

## Метод

- `main` `4aa51116`, сборка `go build ./cmd/evo`, без ключей и конфигурации.
- MCP: `tools/list` сервера `evo mcp` по stdio без `--toolsets`
  (`.github/scripts/tools_list.sh`) — 175 инструментов, 142 664 байта
  ответа; сумма объектов инструментов в компактном JSON — 142 487 байт.
- Группа инструмента — поле `group` из `evo tools list --json`.
- Размер инструмента — его объект `tools/list` в компактном JSON (UTF-8):
  `name`, `description`, `inputSchema`, аннотации. «Описание» и «схема» —
  отдельно `description` и `inputSchema`.
- **Токены не измерены.** Счётчика токенов Claude в окружении «Процесса» нет
  (ни ключа API для подсчёта, ни токенизатора). Байты — факт; токены — только
  пересчёт, и он — гипотеза до подсчёта (правило 6): для английского текста с
  JSON порядка 3–4 байт на токен, то есть 142 КБ — порядка 35–45 тысяч
  токенов. Точный счёт по группам — подсчётом токенов API на ключе владельца
  или клиентом агента; это шаг до порога в CI (пункт 2), а не после.

## Кандидаты на вынос (пункт 3) — по байтам, не по токенам

- **`vpc` → `vpc` + `sg`.** Правила групп безопасности —
  `sg_rule_create` (1 470), `sg_rule_delete` (1 339), `list_security_groups`
  (730): 3 539 байт из 14 049 (25 %). Агент, которому нужны только правила
  доступа, сейчас грузит все 17 инструментов `vpc`; после выноса — 3 и
  ~3,5 КБ вместо ~14 КБ. Набор по умолчанию называет `vpc`: для него вынос —
  смена состава `--toolsets`, ломающее, «Миграция» 1.10 (строка плана).
- **`k8s`** — 19 инструментов без явного ядра: самые крупные — `k8s_helm`
  (1 495), `k8s_plan` (1 484), `k8s_add_addon` (1 484),
  `k8s_add_nodepool` (1 430), `k8s_kubectl` (1 364). Естественное деление —
  кластер (`k8s_create/delete/get/list/plan/options/operation/kubeconfig`),
  группы узлов (`k8s_nodepool*`, `k8s_add_nodepool`), нагрузка
  (`k8s_kubectl`, `k8s_apply`, `k8s_helm`), плагины (`k8s_addon*`,
  `k8s_add_addon`). Выгода — гипотеза: агент нагрузки обычно держит и
  кластер, деление нужно сверить со сценариями агентных прогонов.
- `pg` (15 инструментов, 9 815 байт) — схемы втрое больше описаний; сжатие
  схем дало бы больше выноса — отдельный замер схем (строка плана «замер
  второго резерва»).

## Порог на группу (пункт 2) — предложение

Порог по байтам, а не по токенам, пока нет счёта токенов: факт в CI без
ключа. Например, ни одна группа не больше 20 КБ и не больше 20 инструментов
(сегодня `k8s` — 18,6 КБ и 19, запас — 1,4 КБ и один инструмент): порог
останавливает рост `k8s` до её деления. Числа — по решению «релиза» и владельца; храповик — рядом с
`TestToolsList_SizeBudget` (`internal/mcp`), одна точка потолков.
