«Вторая сессия „Процесса · 1.9“ — инварианты» (замер до первой волны) и
слово «1.9 — релиза» о втором замере (сжатие схем). Только замер и
варианты: кода продукта здесь нет, решения — владельца.

Метки: **факт** — замер или первичный источник; **гипотеза** — вторичные
источники или без проверки; **оценка** — расчёт автора.

## 1. Метод

Бинарь из `main`, `evo mcp` по stdio: `initialize` → `tools/list`, длина
строки ответа в байтах. Сверка — `TestToolsList_SizeBudget` (тело без
конверта JSON-RPC). Состав считается по компактному JSON ответа. Размеры в
`docs/mcp.md` держит `TestDocsExamples_Counts` (допуск 10 %).

## 4. Прогноз 1.9 (оценка)

Новых инструментов по плану версии — 28–39: +26…37 КБ; сквозные аргументы
(теги, списки фильтров) — ещё +3…6 КБ. Итого +29…43 КБ при свободных
~38 КБ: волны В1 и В2 проходят; в верхнем сценарии предел пробивается на
последних волнах.

## 5. Варианты сжатия (факт об экономии, оценка риска)

одному.

## 6. Вывод

Два предела — разные вопросы.

**Байты** (`maxToolsListBytes`, оценка): свободно ~38 КБ, рост 1.9 —
+29…43 КБ.

| Сценарий роста | Без сжатия | С гигиеной (6,1 КБ) | С гигиеной и вариантом 6 (12,6 КБ) |
|---|---|---|---|
| нижний, +29 КБ | запас ~9 КБ | запас ~15 КБ | запас ~22 КБ |
| верхний, +43 КБ | не хватает ~5 КБ | запас ~1 КБ — впритык | запас ~7 КБ |

По байтам сжатие вопрос закрывает: одной гигиены хватает впритык, с
правкой длинных описаний — с запасом. Подъём предела для 1.9 не нужен,
если гигиена сделана до последних волн.

**Число инструментов** (128 у VS Code с GitHub Copilot): сжатие его не
трогает; evo без `--toolsets` выше предела с 1.8, клиент отвечает ошибкой.
Лечит только отбор групп: `--toolsets` по умолчанию или обязательным —
ломающее, по заключению «Риска» 122 — кандидат 2.0.

Инвариант «описание общего аргумента — одно на реестр» заводится вместе
со строкой плана о сжатии, не раньше: до неё закрывать его некому.

### 7.3. Повторы (факт)

- **Описание аргумента повторяет описание инструмента — 0 байт.** Мера:
  предложение описания аргумента от 25 знаков, дословно входящее в
  описание того же инструмента. Пересказ другими словами мера не видит.
- **Одно описание аргумента у нескольких инструментов:** 53 текста,
  повторные вхождения — 11 651 байт. Из них 4 536 — правило согласия у
  `confirmed` (73 инструмента), которое по заключению «Риска» 122 остаётся
  в каждом инструменте. Остальное — 7 115 байт: фильтры списков («Only
  with this in the name», «Only these ids», «Only in this state» — 1 984),
  ожидание (`wait_seconds`, `wait` — 1 750), прочее.

### 7.4. Что из этого резерв (оценка)

| Рычаг | Экономия | Цена |
|---|---|---|
| Повторы описаний аргументов без `confirmed` | до 7,1 КБ | в JSON Schema текст выносится только ссылкой (`$ref`, `$defs`); читают ли её клиенты MCP одинаково — **гипотеза**, без пробы на клиентах не предлагаю. Сокращение самих фраз на треть — около 2,4 КБ |
| Тексты аргументов короче на 10–15 % | 3–4,6 КБ | 616 текстов для модели; по опыту серии сжатия описаний (−4,2 КБ на двух PR вместо плана) правила добавляют текст быстрее, чем он убирается |
| Структура: `type`, имена, `required`, `enum` | около 0 | это и есть контракт (D36: статические правила — в схеме); убрать — значит перенести проверку из схемы в отказ после вызова |
| `minLength`, `format`, `default`, `additionalProperties` | до 2,9 КБ | те же статические правила оси 1; снимать нельзя по D36 |

**Вывод.** Схемы — больше половины ответа, но резерва в них мало:
структура — контракт, тексты плотные. Реалистично 5–7 КБ ценой правки
сотен текстов для модели и одного заключения «Риска» на серию. Вопрос о
числе инструментов (128 у VS Code с GitHub Copilot) схемы не трогают
вовсе. Второй рычаг бюджета — отбор групп (`--toolsets` по умолчанию,
ломающее) или перенос операций, а не схемы; это решение владельца.
