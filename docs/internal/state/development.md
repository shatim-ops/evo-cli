## Постоянные разрешения

- Находки «критично» и «высокая» от «релиза» — без отдельного «да».
- Вливать `main` в свои PR merge-коммитом; ветку чужого PR не трогаю.
- Тема единственного коммита PR — как заголовок PR.
- Перед push — `go test ./...` поверх свежего `main` по коду выхода, не по выводу через `grep`; `gofmt -l .` — последним; `api-contract-check.py --code-only` — при новом обращении к API.
- Строка таблицы плана — под `|---|` (урок #613).
- Объём владельца не сокращаю переносом в бэклог — сначала «релизу» (урок #618).
- «tools/list: +N байт, потому что …» — ровно так (урок #648).
- О платформе — только факт вызова или спецификации; поведение — после пробы (урок #648).
