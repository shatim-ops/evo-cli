# Бриф сессии «Фаза 0 · версия N» (план версии до старта ролей)

Решение владельца 10.11; пилот — 1.9. Порядок — `docs/RELEASING.md`,
«Старт версии — фаза 0». Сессия — Fable, только чтение кода; пишет один PR
в `docs/internal/`, не сливает его, не открывает сессии, не ходит в облако.

## Прочитать

- `CLAUDE.md` целиком, `docs/RELEASING.md`, `docs/internal/standalone/DECISIONS.md`.
- `docs/internal/release-plan.md`: раздел версии N и бэклог с кандидатом N.
- `handoff/<N-1>.md` и `handoff/<N-1>-journal.md` — открытые решения, риски, ретро.
- `docs/internal/risk/register.md` и срезы ролей `docs/internal/state/`.
- evo-internal (через `add_repo`): реестр находок прошлой версии, реестр
  расхождений — только для оценки; сведения о платформе в публичный PR не
  переносятся.

## Сделать (результат — PR, состав по `RELEASING.md`, пп. 1–4)

1. **Объём.** Каждая строка версии — что, почему (номер находки, решение,
   риск), хозяин-роль, цена S/M/L. Отдельно: что предлагаешь перенести и
   почему; что спорно. Вопросы владельцу — одним списком с рекомендацией
   первой; ответы вносит «релиз» до слияния.
2. **Устройство.** Блоки в порядке ценности и риска; зависимости; число
   сессий «разработки» и деление по файлам (общие файлы — названы);
   заранее — что требует заключения «Риска» (правило 7) и инварианта
   «Процесса» (§6) до слияния.
3. **Календарь гейта.** Шаги владельца и живые прогоны с датами: что
   блокирует rc.1, если не сделано к дате.
4. **Срезы ролей** — начальные `state/<роль>.md` для «релиза», «разработки»,
   «Процесса», «Риска» в формате `TestRoleStateFiles`.
5. **Критерии гейта rc.1** — проверяемые, со ссылкой на шаги `RELEASING.md`.

## Правила

- Факт — со ссылкой на файл или PR; оценка — помечена «оценка».
- Не решать за владельца: объём, ломающее, деньги и живое облако — вопросом.
- Не повторять план прошлой версии: каждая строка проходит сверку с `main`
  (сделано ли уже).
- После слияния PR — сессия закрывается; дальше план ведёт «релиз».
