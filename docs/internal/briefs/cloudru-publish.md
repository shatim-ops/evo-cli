# ТЗ: публикация чистой релизной версии evo в официальный репозиторий Cloud.ru (D116)

Автор — «1.9 — релиз (4)», 17.11. Решение владельца 17.11: разработка остаётся в
`evo-cli`; в репозиторий организации Cloud.ru (пока закрытый) по тегу уходит только
чистая релизная версия; переход — по команде владельца одним шагом. Имя репозитория и
планы Cloud.ru — только в `evo-internal`. Заключение «Риска» — до первой публикации.

## 0. Шаги

1. **Скрипт выгрузки** `.github/scripts/release_export.sh <тег|SHA> <каталог>` —
   «Процесс». Делает снимок по списку включения (п. 1), один коммит без истории,
   проверяет инвариант (п. 1) и собирает снимок (`go build ./...`, `go vet ./...`).
2. **Репетиция** — снимок текущего `main` в закрытый репозиторий веткой `rehearsal`;
   пушит владелец своим доступом. Проверяется: состав, сборка, `go install` по пути
   модуля (п. 5), `install.sh` из снимка. Пользователей нет — вреда нет.
3. **Переход** — по команде владельца: снимок тега (п. 3) → `main` и тег в официальном
   репозитории → релиз с бинарями (п. 3) → открытие репозитория → переключение ссылок
   (п. 5). Ветка `rehearsal` удаляется до открытия.
4. **Шаг в `docs/RELEASING.md`** — публикация каждого следующего тега; правило —
   «да» владельца.

## 1. Состав выгрузки — список включения (вопрос «Риска» 1)

Публикуется только перечисленное; всё остальное — нет:

- код продукта: `cmd/`, `internal/` (кроме тестовых данных с внутренними сведениями —
  список даёт «Процесс» по итогам репетиции), `go.mod`, `go.sum`;
- пользовательские документы: `README.md`, `LICENSE`, `CHANGELOG.md`, `SECURITY.md`,
  `docs/` без `docs/internal/`;
- установка: `install.sh`, `install.ps1` (если есть), `.goreleaser.yaml`;
- CI официального репозитория — только сборка и выпуск, без секретов разработки
  (п. 2).

Не публикуются: `docs/internal/`, срезы и журналы ролей, брифы, ретро, планы,
`changelog.d/`, workflow живых прогонов, история коммитов разработки.

**Инвариант:** скрипт выгрузки падает, если в снимке есть путь вне списка включения
или файл, содержащий маркеры внутреннего (`docs/internal`, имена ролей, номера
заключений «Риска»). **История — одним снимком** на тег: коммит «evo vX.Y.Z», без
истории `evo-cli`; ссылка на исходный SHA — в описании релиза.

**Открыто (репетиция):** тесты `internal/testrules` и другие читают `docs/internal`.
Варианты — тесты, которым нужны внутренние документы, не входят в снимок; либо снимок
публикуется без тестов вообще. Решает «Процесс» по итогам репетиции, с заключением
«Риска».

## 2. Ключ организации и запуск публикации (вопрос 2)

- **До перехода и на первом переходе — вручную владельцем**, его доступом; ключа
  организации в `evo-cli` нет.
- **Автоматизация — отдельным решением после перехода:** ключ (GitHub App организации
  Cloud.ru с правом только на этот репозиторий) хранится в окружении `publish` с
  Approve владельца; получает его только job публикации на теге `v*`; код PR ключ не
  получает (`internal/workflows`); запуск — только после зелёного `release`.

## 3. Источник истины для пользователя (вопрос 3)

- Бинари, `checksums.txt`, SBOM и подписи cosign — из релиза официального
  репозитория; собираются тем же goreleaser из того же SHA, что релиз `evo-cli`.
- Проверка — по `checksums.txt` и подписи cosign; идентичность подписи (workflow и
  репозиторий) меняется — `docs/RELEASING.md` и документация проверки называют новую.
- Теги в двух репозиториях: один и тот же номер версии указывает на один исходный
  SHA; расхождение — стоп публикации. До решения об автоматизации релиз в `evo-cli`
  остаётся, в официальном — копия того же содержимого.

## 4. Обратимость (вопрос 4)

- **Обратимо:** снимок и тег в закрытом репозитории; ветка `rehearsal`; переключение
  ссылок в документации и `install.sh` (откат — PR).
- **Необратимо:** открытие репозитория (код мог быть скопирован); проиндексированные
  ссылки; модуль в Go proxy (`proxy.golang.org` хранит версию навсегда, `retract` —
  только пометка). Поэтому до открытия — заключение «Риска» на снимок и «да» владельца.

## 5. Переключение ссылок (вопрос 5)

- `install.sh`, документация, навык агента и образ MCP-сервера указывают на новый
  адрес. Старый адрес `evo-cli` остаётся рабочим — репозиторий не переименовывается
  и не удаляется, иначе имя можно занять и подменить.
- **Путь модуля Go:** сейчас `github.com/shatim-ops/evo-cli`. Варианты: (а) оставить —
  `go install` идёт в `evo-cli`, официальный репозиторий — бинари и документация;
  (б) сменить на путь официального репозитория — ломающее для `go install`,
  «Миграция» и решение владельца. Рекомендация «релиза» — (а) на первом переходе.

## 6. Публикация с дефектом (вопрос 6)

- Убирает владелец (или ключ публикации после автоматизации): релиз помечается
  отозванным, бинари снимаются, выходит исправленный тег; в Go proxy — `retract` в
  следующей версии.
- Дефект безопасности — по `SECURITY.md`, со сроком и уведомлением пользователей.

## 7. Открыто к владельцу

1. Версия первой публикации: последний стабильный тег или 1.9.0.
2. Путь модуля Go — п. 5.
3. Пользователи прежнего продукта в этом репозитории: заметка о миграции — текст и
   место.
