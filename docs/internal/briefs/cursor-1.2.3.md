## Что атаковать

### A. Проверка занятого имени (D20, D21) — главное
- Имя, которое API считает тем же, а `takenName` — другим: регистр, пробелы
  по краям, Unicode-двойники, `name` пустой/из пробелов. Что делает evo, что
  делает API по спецификации (`python3 scripts/cloudru-specs.py <dir>`).
- Статусы: `DELETING`, `FAILED`, `ERROR`, пустой статус, статус в поле
  `state` вместо `status`, неизвестный статус. Освобождают ли имя только
  `DELETED`/`ERASED` — и правильно ли это для каждого из трёх сервисов.
- Постраничный список: шлюз/кластер/балансировщик с тем же именем на второй
  странице. Проверить, что `ListNATGateways`, `mk8s ListClusters`, `ListNLB`
  читают все страницы; если нет — повтор снова создаёт дубль.
- Сбой списка (401, 403, 429, 5xx, обрыв, тело не JSON): отказ до согласия, а
  не создание «на авось»; `reason` и код выхода.
- `k8s_create` без `--name` дважды подряд; с `--product` и без.
- Паритет: `evo snat|k8s|lb create … --json`, `evo tools call …`, MCP stdio и
  MCP HTTP (`--allow-project`, H7) — один `reason`, один код, одно поле
  `existing_id`.

### B. «Миграция» против бинаря
- Каждое «было → стало» раздела «Миграция» CHANGELOG [1.2.3] сверить с
  поведением бинаря на фейке: коды 0/1/2/3, `USAGE`, `AUTH_REQUIRED`,
  `CONFIG_INVALID`, с `--yes` и без, с `--dry-run`, без ключа, без проекта.
- `docs/exit-codes.md`, `docs/mcp.md` (абзац «Цена»), README «Что сейчас
  можно (v1.2.3)» — не противоречат ли бинарю.

### C. Превью #209
- Может ли предупреждение инструмента потеряться: есть в `warning`/`warnings`
  ответа, но нет в `preview.warnings` или в строках CLI; и наоборот.
- MCP по HTTP: маскирование H7 и `preview` — не раскрывает ли превью то, что
  маскируется в остальном ответе (имена секретов, env `ca_deploy`).
- `tariff_url` — у ресурса, который не создаётся (отказ раньше превью), не
  появляется; у шести инструментов — ровно свой адрес.

### D. FIP `deploy_apply` (#213)
- Повтор `deploy_apply` после каждого вида сбоя создания адреса: сколько
  адресов в итоге, что в state и в ответе, что освобождает `destroy`.
- Адрес с именем `<vm>-fip` от прежней ВМ (сирота) — что запишется.

### E. Выбор flavor k8s (#234)
- Каталог в любом порядке, равные cpu/ram, GPU-flavor меньше нужного,
  `cpu`/`ram_gb` из аргументов, явный `flavor` — несуществующий, GPU, в
  другом регистре: что уходит в `POST /v3/clusters` и что показывает
  `k8s_plan`. Совпадают ли `k8s_plan` и `k8s_create` при одном каталоге.
- `k8s_add_nodepool` — тот же выбор своим кодом: те же случаи.
- Видит ли человек размер кластера до согласия (превью `k8s_create` flavor
  не называет — известно, 1.3; блокер ли это по вашему мнению).
- Есть ли такой же дефект «выбранное значение пишется в переменную
  аргумента» в других местах выбора конфигурации (ВМ, DBaaS, `sizer`).

## Как оформить находку

| ID | Где (файл:строка) | Что не так | Воспроизведение (имя падающего теста) | Как исправить | Серьёзность |

ID — `CUR123-N`. Серьёзность: блокер (деньги или согласие: лишний платный
ресурс, действие без согласия, утечка секрета) / важно / мелочь. Тела
падающих тестов — в конце отчёта, рядом с существующими хелперами пакета
(`callNamed`, `raRegistry`, `withParityWorld`, `runCLI`). Указать, что именно
запускалось и с каким результатом; чего не проверял — тоже указать.
