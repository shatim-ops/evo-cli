# Обнаружение и композиция для агента — вход и рамка эксперимента 2.0

Решение владельца 17.11.2026 (опрос «1.9 — релиза (4)»): Code Mode для MCP не реализуется в 2.0 по готовому ТЗ. Его заменяет **единый эксперимент «обнаружение и композиция»** после rc.1 1.9. Хозяин — «Процесс». Поставка рантайма для кода агента возможна только по итогам эксперимента и отдельным решением с номером D и заключением «Риска».

Строка плана, которую решение заменяет: «Code mode для MCP (решение владельца 06.11)», раздел 2.0 бэклога.

## Вход 1 — ТЗ Codex «Локальный Code Mode для evo 2.0» (15.11, на `main` 024cf2e)

Режим `evo mcp --code-mode` только по stdio, двойник в CLI — `evo code run <file.js> --json`.

**Метаинструменты:**
- `evo_search` — поиск по локальному каталогу;
- `evo_execute` — асинхронная функция JS, у которой есть только объект `evo` с разрешёнными чтениями.

**Начальный каталог:** `vm_list`, `vm_get`, `disk_list`, `vpc_list`.

**Лимиты:**

| Что | Предел |
|---|---|
| Исходник | 32 КиБ |
| Память | 64 МиБ |
| Вызовы | 16 |
| Ответ операции | 1 МиБ |
| Итог | 64 КиБ |
| Время запуска | 45 с |

Рантайм-кандидат — QuickJS в WebAssembly под wazero. Замер выигрыша — режимы A–D: полный MCP, штатные toolsets, поиск плюс вызов, поиск плюс программа. Запись — отдельным будущим ТЗ: план с хешем и подтверждением.

**Принято из ТЗ:**
- режим только по флагу и только чтение;
- все вызовы через тот же диспетчер реестра: проверки группы, `CheckArgs`, `--read-only`, `--allow-project`, маскирование;
- скрытая и неизвестная операции отказывают одинаково;
- без молчаливого усечения: превышение — явная ошибка с лимитом;
- вложенные вызовы последовательно, с общим сроком; отмена останавливает JS и облачный запрос;
- порог выигрыша задаётся до прогона, ошибки и тайм-ауты входят в выборку;
- запись — только после модели одобрения плана (строка 2.0 «Независимое одобрение конкретного плана»).

**Изменено решением 17.11:**
1. **Кому это нужно.** Агент с терминалом (Claude Code, Codex) уже составляет чтения через `evo … --json` и `jq`. Выигрыш Code Mode мерить на MCP-клиентах без shell. На клиентах с терминалом — отдельной серией.
2. **Дешёвый конкурент.** Добавлен вариант P: проекция, фильтр, сортировка и лимит в именованных инструментах, без JS. Пример ТЗ («пять крупнейших непривязанных дисков») выражается так. P сохраняет паритет CLI–MCP (§1) и не открывает новую поверхность.
3. **Задачи.** Вместо трёх синтетических задач на четырёх операциях — 20 обезличенных задач из дежурств:
   - 12 частых;
   - 6 с неоднозначным выбором;
   - 2 с отключённой группой.
   Тот же набор отвечает и на вопрос о поиске инструментов.
4. **Многоарендность и удалённый worker** в 2.0 не проектируются: это противоречит D32 (общий сервер не делаем). Остаётся неизменяемый контекст запуска: проект, срок, политика.
5. **Рантайм** — только тестовый прототип вне поставки. Он отвечает на вопросы:
   - шесть целей сборки;
   - размер бинаря и холодный старт;
   - гарантированное прерывание и предел памяти;
   - лицензия и цепочка поставки (cosign, SBOM).
6. **Бюджет вызовов** считает HTTP-запросы к облаку, а не вызовы evo: пагинация списков.
7. **Недоверенный текст.** Метка `untrusted` на весь запуск допустима как консервативная. Человеческий вывод `evo code run` проходит общую очистку и инвариант #2029.

## Вход 2 — бэклог Астры (15.11, на `main` 024cf2e), пункты 110-03 и 20-03

Это два исследования: поиск инструментов и композиция чтений. Оба сравниваются с лучшим ролевым профилем и `agent_skill`. Оба порога предложены до опыта:

| Пункт | Что мерить | Порог |
|---|---|---|
| 110-03 | поиск исправляет ошибки выбора инструмента | половина ошибок или ≥20 % времени/токенов |
| 20-03 | композиция экономит токены | ≥30 % медианы токенов при росте p95 не больше 10 % |

## Эксперимент

**Варианты:**

| Вариант | Что это |
|---|---|
| B | Штатный ролевой профиль с `agent_skill` |
| P | Проекция и фильтры в именованных инструментах |
| S | Поиск, затем один вызов |
| D | Поиск и программа: прототип рантайма в тестовом адаптере |

**Условия:** одна модель, одна версия клиента, одинаковые права и фикстуры, новые сессии, случайный порядок вариантов. Серии клиентов без shell и с shell идут отдельно.

**Метрики:**
- доля верных ответов;
- токены на верный ответ, с учётом кеша;
- ходы;
- HTTP-запросы к облаку;
- p50 и p95 до ответа;
- облачных записей, раскрытий секретов и обращений в чужой проект — ровно ноль.

**Решение по итогам:**
- Поставка D (preview Code Mode) — только если D бьёт лучший из B и P не меньше чем на 25 % токенов на верный ответ, а доля верных не ниже.
- Если выигрыш даёт P — делаем P: это обычная правка реестра.
- Если выигрыш даёт только поиск — решаем отдельно о поиске без JS.

Числа порогов — гипотезы до замера (§0, правило 6).

**Замер на 17.11:** `tools/list` на `main` — 174 инструмента в 25 группах, 141 379 байт. В v1.8.2 было 124 515 байт (таблица ТЗ Codex).
