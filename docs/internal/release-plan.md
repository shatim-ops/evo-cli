## Раскладка 1.4–2.0 (решение владельца 23.10)

Принцип: сначала глубина на ядре (ВМ, сеть), потом ширина. По операциям над ВМ evo оценивают первым делом, и по ним он отстаёт даже от `hcloud` и `doctl`. Основа — анализ Fable (`docs/internal/audits/ops-gap-1.4.md`, #290), с правками «1.3 — релиза». Каждая minor-версия идёт по `docs/RELEASING.md`: rc.1 → догфуд → полный аудит Fable → cloud-e2e на коммите тега → стабильный тег. Для 1.4 и 1.5 (меняют ВМ и сеть) — ещё волна Grok «агент-оператор». Каждая новая операция: инструмент реестра и команда (`CLISpec`), сначала тест, превью и согласие для платного и прерывающего сервис, идемпотентность по классу D26 (`already_stopped` и т. п.), сценарий cloud-e2e. Миры паритета и матрицу сбоев под новые вызовы API (`set-power`, группы, подсети) готовит «Процесс · N» до разработки.

Перенесено решением владельца 23.10:
- Data Platform, Workflow Studio и Repo — с 1.4 на 1.7;
- цена из калькулятора, номер договора и проба НДС — с 1.4 на 1.6, вместе с потолком стоимости: ему нужны цены всех сервисов;
- режим без удалений и набор инструментов по правам ключа — с 1.4 на 1.6;
- проверка безопасности созданных ресурсов — с 1.4 на 1.5, к группам безопасности.

Если у Data Platform появится внешний срок, 1.7 меняется местами с 1.6.

## 2.0 — ломающие

- `--port` без источника — отказ; своя группа на ВМ по умолчанию, если её не сделали умолчанием в 1.5.
- Пароль ВМ — только по запросу (`vm_set_password`), а не в ответе создания (Р6).
- `status` и состояние без привязки к каталогу создания (G3): ресурс находится через API.
- Снятие совместимости с `cloudru-vm` (`docs/rename.md`).
- Массовые операции (`vm stop --tag …`) — только вместе с потолком стоимости и режимом без удалений.
- Один `status` у `destroy` развёртывания на обеих поверхностях; предложение — `destroyed`, как в CLI с v1.0 (решение владельца 24.10; в 1.4 MCP получает поля ВМ, `status` пока разный).
