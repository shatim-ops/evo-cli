Правила графика:

1. **Каждый живой запуск — только по «да» владельца.** Фаза 0 в облако не
   ходит и прогонов не запускает. Запускает «1.9 — релиз»; job в окружении
   `cloud-e2e` дополнительно ждёт Approve владельца в Actions
   (`docs/RELEASING.md`, шаг cloud-e2e).
2. **Это пробы API, а не cloud-e2e кандидата.** Кода операций в evo ещё нет:
   проба шлёт запросы напрямую (как `cmp7`, `p36` во входе `probes`
   `cloud-e2e.yml`) и пишет коды HTTP, имена полей, последовательность
   состояний и форму операции — без значений, ID и адресов
   (`.github/scripts/redact.sed`). cloud-e2e кандидата 1.9 — отдельный шаг
   гейта (раздел 4).
3. **Уборка — в том же PR, что проба (ось 3).** Каждый ресурс пробы назван
   `evo-e2e-<проба>-<прогон>`, удаляется шагом `always()` своего job, а
   `cleanup_only` умеет найти и удалить его вид. Нового вида ресурса
   (резервная копия, план защиты, тег, вторая группа узлов) в `cleanup_only`
   сейчас нет (факт: описание входа `cleanup_only`, `cloud-e2e.yml:144`) —
   проба без расширенной уборки не запускается.
4. **Вывод о платформе — из двух прогонов.** Один прогон — гипотеза; в
   реестр расхождений и в строки плана о цене идёт только «2 из 2»
   (CLAUDE.md §0).
5. **Результаты проб** — в `evo-internal/runs/`, пункты реестра расхождений —
   в `evo-internal/discrepancies/`; в публичные PR — только «проба Г-N
   сделана, прогон №».
6. **Строка о цене — после пробы цены** (решение владельца 04.11): операция,
   чья проба цены не сделана, получает превью «цена неизвестна, ресурс
   платный», а не число.
