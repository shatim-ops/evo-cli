## Проверено, не сломалось

1. **State и конкурентность.** Сообщение `state.Lock` не предлагает удалить `state.lock`: «блокировка снимается, когда тот процесс закончит работу» (`internal/state/lock.go`). Второй `Lock` сразу `STATE_LOCKED` — уже `TestLock_SecondHolderIsRefused`. `Deploy` без `--dry-run` берёт лок; `--dry-run` лок не берёт и файл не пишет. Запись — `CreateTemp` + `Sync` + `Rename`, читатель видит старый или новый файл целиком. Пустой `VMID` в `destroy` не делает `DELETE /vms/` — `TestDestroy_RecordWithoutVMID`. `Read` отвергает `version` больше 1 — `TestRead_NewerVersionRefused`. `version` не число и битый JSON дают ошибку `Unmarshal`, то есть `STATE_CORRUPTED`, не пустое состояние. Запись `version: -1` (целое, не больше 1 и не 0) читается как допустимая: это уже ручная порча файла, отдельным дефектом не ставил. `stack_apply` на job `error` продолжает pending-шаги — известно: BACKLOG [qa-mcp]. `job_id` с `../` закрыт `valid` именем и `LockJob`. Пустой `plan_id` и `../` не проходят `deployplan.validPlanID`.

2. **Обрыв на каждом шаге.** По коду и уже лежащим тестам, новых падающих тестов нет. `409` на создании — `provision.CreateRejected`: чужая ВМ не усыновляется, boot FIP отпускается (`engine/deploy.go`, `tools.handleProvision`); это `docs/exit-codes.md` (у `provision` код 1 `USAGE`, у `deploy` код 2 `CONFIG_INVALID`). `FindCreatedVM` берёт первую ВМ с тем же именем и `created_time` не раньше старта минус 5 минут; окно в коде названо сдвигом часов, не обещанием exit-codes. Порядок списка «свежие первыми» записан в `docs/internal/api-contract.md` как причина, почему новая ВМ на первой странице — см. «нужна живая проверка», если порядок на бою другой. Ошибка `releaseBootFIP` печатает адрес и id. Неудачная запись state после создания ВМ называет id (`VM %s was created, but the state file could not be saved`). SIGINT и отмена контекста на ожидании ВМ идут в один `handleInterrupt`. `destroy`: `404` в том же проекте — «уже удалена», FIP отпускается; чужой `project_id` и `404` — `CONFIG_INVALID`, запись остаётся. Строка BACKLOG «перенесено» про `ReleaseBootFIP` вне ответа `provision` по коду уже закрыта: `fipLeftAnswer` кладёт `floating_ip_id` в ответ. Повторно не заводил.

3. **Окружение.** Находки R2-3 и R2-4. Приоритет флагов, env, `.evo.yaml` и профиля и правило «пустая переменная = не задана» в `config.applyEnv` совпадают с `docs/auth.md` §7; пара ключа из env берётся целиком. `CLOUDRU_API_KEY` режется по первому двоеточию, секрет с двоеточием сохраняется. `image` и `image_id` в одном слое — `CONFIG_INVALID`; верхний слой побеждает в `pickImage`. `kubetools.childEnv` оставляет `HTTPS_PROXY`/`NO_PROXY` и снимает `CLOUDRU_*` и `MCP_BEARER_TOKEN` — тест уже есть.
