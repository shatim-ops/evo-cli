# План: cloudru-vm → самостоятельный CLI + MCP для управления инфраструктурой Cloud.ru

Исполнитель кода — Opus 5.5. Каждый этап — отдельный самодостаточный бриф
(`docs/internal/standalone/stages/NN-*.md`), который можно отдать агенту без истории
этого диалога. Этапы упорядочены так, чтобы не конфликтовать по файлам.

Решения владельца — `DECISIONS.md`. Готовые промпты для запуска сессий и
шаблон PR — `KICKOFF.md`. Старт: этапы 0+1 и 6 параллельно, PR на каждый
этап, мержит владелец.

## Протокол работы исполнителя (для каждого этапа)

1. Прочитать `00-audit.md` (разделы 1–2) и бриф своего этапа. Больше ничего.
2. Не выходить за «Scope». Найденное вне scope — записать в `docs/internal/standalone/BACKLOG.md`, не чинить.
3. Перед пушем: `gofmt -l . && go vet ./... && go test -race -count=1 ./...`. На этапах 1–2 допустимо, что `internal/engine` идёт 91 с; после этапа 6 — не более 10 с суммарно.
4. Один этап — одна ветка — один PR. Коммиты по-русски, в стиле репозитория («что и почему», без «feat:»).
5. Не трогать сетевые эндпоинты и формат auth без явного указания в брифе.
6. Критерии приёмки в брифе — проверяемые команды. Если критерий не выполним — остановиться и написать почему, а не ослаблять критерий.

## Что сознательно НЕ входит в первый публичный релиз

- OS keyring (macOS Keychain / Windows Credential Manager / Secret Service): файл 0600 + профили достаточны; keyring — v1.1.
- Нотаризация macOS и Authenticode: только если у компании уже есть сертификаты.
- Первоклассные деревья команд для kafka, redis, dns, nlb, certmanager, ar, ca, stack, monitoring, audit, billing, admin, snat — через `tools call` в v1.0, деревья по мере спроса.
- Поддержка `build:` и нескольких compose-файлов в `deploy`.
- Переопределение базовых URL API через env.
