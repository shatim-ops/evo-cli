# Передача цикла 1.9 на другую учётную запись (эстафета до 24.11)

Решение владельца 18.11: лимит текущей учётной записи кончается; цикл
разработки 1.9 переходит на другую учётную запись до вторника 24.11.
**Момент передачи — по команде владельца** (ожидается вечером 18.11). До
команды работа идёт как обычно; по команде «релиз (4)» обновляет раздел 4
(снимок), все роли — свои срезы, и только после слияния этих правок
владелец открывает оркестратор.
Документ — единственная точка входа. Он не заменяет `CLAUDE.md` §0, а
говорит, в каком порядке поднять роли и откуда взять состояние.

Правило передачи (`CLAUDE.md` §0, правила 5 и 8(5)): состояние живёт в
файлах и на GitHub, а не в истории сессий. С открытия преемника прежняя
сессия роли не пушит и не выдаёт номеров. Всё, что не записано в файле,
PR или issue, считается потерянным — поэтому сначала сверка, потом работа.

## 1. Что сделать владельцу до старта (новая учётная запись)

1. **GitHub.** Подключить GitHub к claude.ai (Settings → Connectors) с
   доступом к `shatim-ops/evo-cli` и `shatim-ops/evo-internal`; при
   необходимости — установить Claude GitHub App на организацию
   `shatim-ops`.
2. **Окружение.** Облачное окружение с обоими репозиториями; сеть —
   неограниченная (как «Default» прежней учётки), скрипта установки нет —
   Go и инструменты ставятся сессиями сами.
3. **Модели (правило 8(1)).** «Риск» — верхний уровень; «релиз»,
   разработка, «Процесс» — рабочий. Аудит Fable — модель Fable. Модель
   называет владелец при открытии сессии.
4. **Не больше шести сессий одновременно** (правило 8(2)).
5. Открыть **одну** сессию — оркестратор (раздел 2). Остальные она
   откроет сама.
