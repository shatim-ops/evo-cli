# Догфуд 1.3: отчёт о сценарии в Jira SM и сводка

Решение владельца 25.10.2026: волна догфуда 1.3 — первая с обратной связью
через Jira SM, а не через формы GitHub. Заявку пишет участник; переносом в
issue занимается сессия «Разбор волны догфуда» (`feedback-triage.md` —
правила разбора те же). Этот файл — текст шаблона заявки, правило переноса и
правило сводки. Ключ проекта Jira, адреса и имена участников сюда не
пишутся: репозиторий публичный.

Поля шаблона повторяют обязательные поля `.github/ISSUE_TEMPLATE/bug.yml` и
`checkin.yml`: без них перенос теряет воспроизводимость — версии, ОС,
точной команды, вывода и кода выхода хватает, чтобы разбор написал
падающий тест на фейках, а без них — нет.

## 1. Шаблон заявки (вставить в описание заявки Jira SM)

Одна заявка — один сценарий или одна проблема. Поля со звёздочкой
обязательны; заявку без них разбор вернёт с просьбой дополнить.

```
[evo 1.3] <сценарий или проблема — одной строкой>

* Версия: <вывод `evo version`, первая строка>
* ОС: macOS / Windows / Linux / Windows + WSL
* Окружение: <оболочка; корпоративный прокси да/нет; для MCP — клиент и модель>
* Как запускали: CLI в терминале / MCP через агента (какого) / MCP в Cloud.ru AI Agents
* Сценарные скиллы: со скиллами (какие, версия) / без скиллов / не знаю
* Сценарий: <что хотели сделать: «развернуть compose со ссылкой», «PG подешевле», «убрать всё с префиксом» …>
* Точная команда или запрос агенту:
  <команда целиком; для агента — текст запроса дословно>
* Что произошло (вывод):
  <вывод или ответ инструмента; ID, IP, имена ресурсов заменить на <uuid>, <ip>, <имя>>
* Код выхода: <`echo $?`; для MCP — isError и reason из ответа>
* Что ожидали:
  <одна-две строки>
* Где, по-вашему, проблема: evo / платформа Cloud.ru / не знаю
* Остались ли платные ресурсы: ничего лишнего / создан лишний (дубль) / остался после удаления или ошибки / не знаю
  (проверка: `evo vm list`, `evo vpc fips`, `evo disk list`, `evo pg list`)
  Повторяется: всегда / иногда / один раз / не проверял
  Минут на сценарий: <число>
  Итог сценария: получилось / частично / не получилось
  evo doctor: <вывод `evo doctor`, если проблема в установке или ключе>
```

Ключи, секреты и пароли в заявку не вставлять никогда — ни в вывод, ни в
команду (`evo secret value`, `--password`).

## 2. Перенос в GitHub (сессия «Разбор волны догфуда»)

- Переносится всё, кроме вопросов, на которые разбор отвечает в самой
  заявке. Ошибка evo — issue по форме `bug.yml`, идея — `idea.yml`;
  платформа — пункт реестра `cloudru-discrepancies.md` (живое — с прогоном,
  без проверки — «гипотеза»).
- **Обязательные поля не на месте** (версия, ОС, команда, вывод, код
  выхода, ожидание, «evo или платформа», платные ресурсы) — заявка не
  переносится: одна просьба дополнить в заявке, и всё.
- **Jira — внутренняя, GitHub — публичный.** При переносе разбор сам
  заменяет реальные ID проектов, ВМ и ресурсов, IP, Key ID, имена ресурсов
  и доменов, имена и логины людей на `<uuid>`, `<ip>`, `<имя>`. Ссылка на
  заявку в issue — только номер заявки без адреса; ключ проекта и имя
  участника в issue не пишутся.
- «Остались платные ресурсы» с любым ответом, кроме «ничего лишнего», —
  разбор первым делом (как метка `деньги`, `feedback-triage.md`): ресурс
  назван, участнику — как удалить, и только потом причина.
- Один дефект в нескольких заявках — одно issue, остальные заявки
  ссылаются на него.

## 3. Сводка (раз в неделю и после итоговых заявок волны)

Сессия «Разбор волны догфуда» — в свою сессию и релизу 1.3.x одним
сообщением; в репозиторий — только итог в `handoff/<версия>.md`
(«Метрики версии»), без имён участников:

| Что | Как |
|---|---|
| Покрытие | таблица «область протокола (`dogfood-protocol.md`) × число участников»; область, у которой меньше двух участников, — отдельной строкой |
| Сценарии | по полю «Сценарий»: со скиллами / без — успех, частично, нет; минуты (медиана) |
| Деньги | все заявки с «Остались платные ресурсы» кроме «ничего лишнего» — номер заявки и что осталось |
| Дефекты | перенесено: ошибок evo N (issue), платформы M (пункты реестра), идей K; не перенесено из-за неполных полей — L |
| Ускользнувшие | каждая ошибка evo из заявок — строка «ускользнул: догфуд» (`CLAUDE.md` §5) |

Итог скиллов — к порогу §10 `docs/internal/skills/spec.md`, вместе с
замером волны 3 Grok.
