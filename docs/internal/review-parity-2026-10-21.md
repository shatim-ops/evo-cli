## Что проверял и не сломал

Покрытие: 154 инструмента, у каждого ровно одна команда; 21 локальная команда с причиной; 9 команд движка (`TestParity_CommandsAndTools`). `CLISpec.None` ни у кого не заполнен. Второй команды на инструмент этот тест не находит. Обход ограничителя через пустой `None`, команду без `evo.tool` или группу без сводки не воспроизвёлся: существующий тест на закрытые списки зелёный.

Аргументы. Общая проверка схемы на всех поверхностях (`checkedArgs` в реестре, `CheckArgs` у деревьев и `evo tools call`). Обязательные поля пустой строкой — ошибка использования, не код 5. Секреты `--password-file` / `--value-file` / `--private-key-file`: файл и значение дают один аргумент (`TestSecretFiles_SameArgumentAsValueFlag`). Пары «одно из» (`vm_id`/`name`, `image`/`image_id`, `id`/`cluster_id`, `value`/`values`, `vm_id`/`targets`) идут через `oneOfArgs` и `aliasArg`: оба заданы — отказ, одни пробелы — «пустое значение», пробелы по краям срезаются. Это один обработчик, поэтому CLI и MCP здесь не расходятся. Расхождение числа `1e3` — RP-8. `NaN` флаг числа не пропускает в обработчик (`coerceArg`).

Ответ. Существующие тесты равенства `--json` и JSON инструмента (включая закрытый `jsonAliasCompat`: журналы текстом, `deploy`, `destroy`, `doctor`, алиасы до v2.0) в полном прогоне не падали. Код выхода и `reason` на ошибке схемы — `USAGE` / 1 на CLI и `isError` с тем же `reason` у инструмента.

Превью и согласие. `NeedsConsent` — единая точка для `--read-only`: частичные только `k8s_kubectl` и `k8s_helm`, их предикаты совпадают с гейтом обработчика. `stack_status` при `Registry.readOnly` задание не двигает. Два `deploy_apply` одной ВМ сериализует `LockApply` (второй отказ, а не вторая ВМ). `secret_value` и `cert_private_key` требуют согласия и на CLI (`--yes`), и в MCP (`confirmed`).

Язык. `evo mcp` ставит английский до разбора своих ошибок (`runMCP`, REL-12). Русская справка деревьев без `confirmed=true` — существующие тесты зелёные. Позиция фразы согласия — RP-6.

HTTP H1–H11. Закрытый перечень на месте (тест политики в полном прогоне зелёный). По stdio без `--read-only` лишних ограничений нет; `--allow-project` (H9) и `--read-only` (H11, а с ним H3, H6, H7) действуют на обоих транспортах. `k8s_kubectl describe secret` и `get secret -o yaml` в этом режиме отвергаются. `k8s_kubeconfig` с токеном по умолчанию отвергается; `embed_token=false` остаётся. `doctor` по HTTP выключен (H10). `project_id` у `provision`, `deploy` и `billing_*` проходит через override проекта — чужой `project_id` при флаге даёт `CONFIG_INVALID` (существующий тест). Дыра — договор без `project_id`, RP-1.

`--read-only`. Список инструментов прячет те, кому согласие нужно всегда. Вызов, который меняет облако или печатает секрет kubectl, упирается в `NeedsConsent` или в проверку kubectl/helm до обработчика. Отдельного обхода через `stack_status`, плагин или `-f`/`-k` не нашёл: такие аргументы и есть согласие, и запрещены проверкой.

Совместимость с 1.1.0. Имена свойств схем у 117 инструментов, чья схема задана литералом, те же. Новые инструменты — `whoami` и `doctor`. Укорочения `provision`, `marketplace_list` (константа описания), `stack_plan` и `image_create.image_metadata` совпадают с журналом. Незаписанный рост трёх текстов — RP-5. Оба бинаря 1.1.0 и 1.2 на живом облаке не гонялись: ключей нет. Алиасы `list-zones`, `list-images` и скрытый `--force` у `destroy` в дереве есть.

Документы. `docs/commands.md` и `docs/tools.md` сверяются с бинарём тестами генерации — они зелёные. Локальные команды в каталоге помечены. Утверждения README про Kafka, DNS и PostgreSQL называют команды `evo kafka`, `evo dns`, `evo pg`. Расхождение руководства — RP-7.

Маскирование, которое совпало с правилом и в находки не вошло. Вложенная JSON-строка под нейтральным ключом не разбирается: правило именное. `nextPageToken` и `page_token` не маскируются. Строка под `password` маскируется, массив строк под `passwords` тоже. `kubeconfig` не маскируется и закрыт H6, когда внутри токен.

Классы входов: фиктивные UUID `00000000-…`, договор `agr-review`, JSON с числом, bool и точкой в имени поля, флаг `--size-gb 1e3`, тексты `tools/list` против тега, абзац `docs/guide.md`. Секретов и адресов вне `192.0.2.0/24` / документации нет.
