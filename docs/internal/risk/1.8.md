## Заключение 5. D55 — вход агента: evo создаёт сервисный аккаунт и ключ под токеном человека (резерв, #563)

**Шесть вопросов.**

2. *10×.* Правило «старый ключ evo на этой машине удаляется»: несколько
   агентов на одной машине (контейнеры с одним именем хоста) — вход одного
   удаляет ключ другого, если «эта машина» определяется по имени (R-25, 2/2).
3. *Человек недоступен.* Ключ истекает через 30 дней; агент без присмотра

4. *Сценарий у людей.* Каждый пользователь evo; сегодня — ключ в консоли и

5. *Доказательство.* Ответы IAM частично гипотезы (`aud`); контракт — после

6. *Цена разворота.* D51 → D55 уже один разворот; до `internal/login` цена

**Матрица.** Агент автономен × безопасность 2/3 (R-24); человек + агент ×
надёжность 2/2 (R-25); агент автономен × отказоустойчивость 2/1 (R-26);

**Условия к тексту D55.**

   время модуля, иначе H14 нарушится чужим кодом (R-28, 2/2). Рост
   `tools/list` — модуль выключен по умолчанию (принято).
3. *Человек недоступен.* Чтение — денег нет. Не применимо.
4. *Сценарий у людей.* «Одна точка входа» — решение владельца, бриф сам в

5. *Доказательство.* Сравнение с Docker, Cloudflare, Block — вторичные
   источники; инцидентов нет. «Чтение не пишет» недоказуемо тестом — бриф

6. *Цена разворота.* Шаг 0 окупается сам; шлюз — M «разработки» плюс

## Заключение 7. D72 — именованные токены HTTP `MCP_BEARER_TOKEN_<имя>` (резерв, план 1.7 → 1.8)

Исход: **приемлем при условиях** (R-31…R-33); одно условие обязательно
до любого именованного токена — R-32.

**Факты (код `873d6b4`).** Один токен `MCP_BEARER_TOKEN`, сравнение
постоянного времени (`internal/mcp/http.go:204`), не короче 32 символов
не на loopback (`internal/cli/mcp.go:344`). Общий сервер в облаке не
делается (D32): HTTP — для локальных клиентов. Журнал D46 пишет `Session`
(процесс), D43 (намерение и итог мутации) не реализован — строка бэклога
1.8. Источник решения — сравнение с клиентами AWS/GCP/Azure (Grok 26.10,
S5), не инцидент.
**Найдено при сверке:** маска логов `internal/log/sanitize.go:25` ловит
`MCP_BEARER_TOKEN=…`, а `MCP_BEARER_TOKEN_agent=…` — нет; фильтр окружения
для `kubectl`/`helm` `internal/kubetools/kubetools.go:100` сравнивает имя
целиком (`name == "MCP_BEARER_TOKEN"`) — именованный токен уйдёт в
окружение дочернего процесса.

**Шесть вопросов.**
1. *Обход моделью с терминалом.* Имя токена говорит, какой HTTP-клиент
   вызвал evo, а не чьим ключом тронуто облако: тем же ключом та же модель
   через CLI пишется в журнал как сессия CLI. Отзыв токена агента не отзывает
   ключ облака на той же машине. D72 даёт атрибуцию, не границу; текст D72
   обязан это сказать, иначе «отзыв по агенту» прочтут как отключение агента
   (R-31, 2/2).
2. *10×.* N токенов в окружении одного процесса; смена одного — перезапуск
   сервера и обрыв остальных клиентов (окружение читается на старте,
   `mcp.go:238`). Назвать в D72; перечитывание по сигналу — выбор реализации
   (R-33, 1/2).
3. *Человек недоступен.* Денег нет. Не применимо.
4. *Сценарий у людей.* Один человек, несколько агентных клиентов на одной
   машине по HTTP (`agent setup` пишет HTTP-конфиг шести клиентов) — сценарий
   есть, частота не измерялась. Гипотеза.
5. *Доказательство.* Рекомендация сравнения, инцидента нет; «кто вызвал» в
   D43 — зависимость от нереализованного.
6. *Цена разворота.* Низкая, если `MCP_BEARER_TOKEN` остаётся рабочим
   (имя «default»); его снятие — ломающее.

**Матрица.** Человек + агент × безопасность 2/3 (R-32: утечка именованного
токена в лог и в окружение `kubectl`/`helm`), 2/2 (R-31); 10× × надёжность
1/2 (R-33). Остальные — «—».

**Условия.**

  уходит ни в один канал» (класс теста уже в плане 1.8 для `login`); это

- Порядок: после D43 (поле «кто вызвал» некуда писать до него) — либо D72
  пишет имя в журнал D46 сейчас, что дешевле и не ждёт D43.
- Не ломающее: `MCP_BEARER_TOKEN` остаётся.
