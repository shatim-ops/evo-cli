## evo 1.9.0

Операции второго дня, резервные копии и журнал изменений; значения облака в
ответах MCP помечены как недоверенные. Полный текст — в `CHANGELOG.md`, раздел
1.9.0. Ломающие изменения — раздел «Миграция» версии 1.9.0: было → стало → что
поменять. Подпись архивов и `checksums.txt` проверяется по `docs/install.md`.

### Операции второго дня

- **ВМ:** `evo vm start`, `stop`, `reboot`, `resize`, `console` — с превью,
  согласием и безопасным повтором, одинаково в CLI и MCP.
- **Kubernetes:** группы узлов — `evo k8s nodepool-get`, `nodepool-scale`,
  `nodepool-delete`, ход операции — `evo k8s operation`.
- **Сеть:** правила групп безопасности — `evo vpc sg-rule-create` и
  `sg-rule-delete`; пустой `cidr` или `remote_group` — отказ, а не «весь
  интернет».

### Резервные копии

- `evo backup create`, `list`, `get`, `restore`, `delete` — копии ВМ и дисков,
  восстановление копии диска в новый диск.

### Журнал изменений

- Каждый вызов, который меняет облако, пишется в `.evo/history/`. `evo history`
  читает журнал, `evo history --check` называет то, чего ключ уже не видит.
  Журнал чистится сам: 90 дней и 64 МБ, живое не удаляется.

### Безопасность и надёжность для агента

- Значения облака в ответах инструментов помечены полем `_untrusted`.
- Отказы по форме аргумента не повторяют введённое значение — ни строку, ни
  число; `evo mcp healthcheck` не печатает пароль, query и текст статуса
  сервера.
- Повтор платного создания после потерянного ответа, ответа без квитанции или
  удаления «уже нет» ресурса, который ещё создаётся, не создаёт второй ресурс.
