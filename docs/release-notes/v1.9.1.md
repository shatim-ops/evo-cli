## evo 1.9.1

При переходе на 1.9.1 проверьте скрипты, которые используют `evo redis list` и `evo kafka list`. В 1.9.0 тело страницы `null` или элемент `null` в массиве `clusters` могли дать успешный, но неполный результат. В 1.9.1 CLI возвращает код 5 (`API_ERROR`), а инструменты MCP `redis_list` и `kafka_list` возвращают `result.isError: true`. Успешная пустая последняя страница с `{"clusters":[]}` по-прежнему завершает выдачу.

Проверьте код выхода или `result.isError` до чтения строк. При ошибке остановите действия, зависящие от списка, и повторите чтение, когда сервис сможет вернуть все страницы.

Перед созданием `evo redis create` и `evo kafka create` проверяют имя по полному списку. Если страница неполна, CLI возвращает код 5, а инструменты `redis_create` и `kafka_create` — ошибку до отправки запроса на создание. При `evo mcp --allow-project` проверка принадлежности ID кластера Redis или Kafka проекту также требует полного списка. При ошибке вызываемая операция не выполняется.

После удаления ВМ `evo destroy --json` сообщает `status: partial` и `cleanup_pending: true`, когда остался адрес или правило либо их уборку не удалось подтвердить. Код выхода по-прежнему 0. В скрипте проверяйте `status == "destroyed"` перед следующим шагом.

Подробности перехода — в разделе «Миграция» версии 1.9.1 в [CHANGELOG.md](../../CHANGELOG.md#миграция).
