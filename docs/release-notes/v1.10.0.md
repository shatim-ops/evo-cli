## evo 1.10.0

При отборе по имени VPC команды `evo vpc subnets`, `evo lb list` и `evo tg list` проверяют все страницы каталога сетей выбранного проекта. Раньше совпадение на первой странице могло дать выборку и код 0 при повреждённой следующей странице. Теперь в таком случае запрос к целевому списку не выполняется. CLI возвращает код 5 (`API_ERROR`). Инструменты MCP `list_subnets`, `lb_list` и `tg_list` возвращают `result.isError: true` с причиной `API_ERROR`.

В скрипте проверяйте код выхода до обработки строк, в MCP — `result.isError`. При ошибке повторите чтение после восстановления каталога. Если UUID сети уже известен, передайте его в `--vpc-id` или в аргумент MCP `vpc_id`. Для фильтров по UUID и прямого вызова `vpc_list` поведение сохраняется.

Если потерян ответ на создание DNS-записи, статического маршрута или платного SNAT-шлюза, повтор с прежним согласием мог отправить второй запрос. Теперь проверьте результат в списке записей зоны, маршрутов VPC или шлюзов проекта и запросите новое согласие человека. Скрипт CLI при вопросе получает код 3. В MCP запрос без ID сессии при неизвестном исходе удерживается. Для продолжения используйте сессию с выданным при `initialize` заголовком `Mcp-Session-Id`, stdio или интерактивный терминал. [Порядок восстановления](../mcp.md#network-create-recovery).
