# Журнал сессии (`evo diag`)

Журнал сессии — локальный файл с тем, какие инструменты evo вызывались и чем
закончились вызовы. Он нужен для догфуда: показывает поведение evo в живой
работе агента и человека. Решение — D46.

## Включить, посмотреть, выгрузить

```sh
evo diag on        # один раз: включает журнал в config.yaml
evo diag status    # включён ли, сколько записей, размер, период
evo diag export    # копирует журнал в evo-journal-<время>.jsonl в текущем каталоге
evo diag off       # выключает; файл остаётся
```

- Включается в конфигурации, а не флагом запуска: MCP-клиент запускает
  `evo mcp` сам, и флаг пришлось бы дописывать в его настройки. Настройка
  читается на каждом вызове, перезапускать MCP-сервер не нужно.
- Один файл на весь догфуд: `journal.jsonl` рядом с `config.yaml`
  (путь показывает `evo diag status`), права `0600`.
- Лимит — 16 МБ на весь период (порядка пятидесяти тысяч вызовов). При
  переполнении журнал пишет последнюю запись `"event":"journal_full"` и
  больше ничего не пишет; `evo diag status` и `evo diag export` говорят об
  этом. Начать заново — выгрузить и удалить файл.
- `evo diag export` можно выполнять в любой момент: журнал остаётся и
  продолжает расти. `--out` — свой путь; существующий файл не
  перезаписывается.
- Журнал никуда не отправляется: файл передаёте вы.

## Что в записи

Одна строка JSON на вызов инструмента — через CLI и через MCP-сервер
одинаково:

| Поле | Что |
|---|---|
| `time` | время вызова, UTC, до секунды |
| `evo` | версия evo |
| `session` | метка сессии: один процесс evo — один вызов CLI или один запуск MCP-сервера |
| `surface` | `cli`, `mcp-stdio` или `mcp-http` |
| `os` | ОС и архитектура |
| `tool` | инструмент |
| `args` | **имена** аргументов, которые объявляет схема инструмента; значений нет |
| `unknown_args` | сколько аргументов схема не знает (их имена — текст вызывающего, в журнал не идут) |
| `depth` | 1 и больше — вызов, который сделал другой инструмент (шаг стека) |
| `confirmed` | вызов пришёл с согласием: `confirmed=true` в MCP, `--yes` или «да» на вопрос в CLI (у `evo deploy` и `evo destroy` — и когда спрашивать было не о чем) |
| `preview` | ответ — превью с вопросом о согласии; у `evo deploy` и `evo destroy` — и `--dry-run` |
| `error`, `reason` | вызов закончился ошибкой и её код (`NOT_FOUND`, `USAGE`…); код не из `internal/errors` — `OTHER` |
| `ms` | длительность, мс |
| `bytes` | размер ответа в байтах — грубая оценка веса ответа в контексте агента, не токены |

Чего в журнале нет: значений аргументов, ответов, текстов ошибок и
подсказок. Поэтому в нём нет id ресурсов, адресов, путей и секретов, и
маскировать нечего. Токены агента evo не видит: их считает клиент модели.

## Ограничения

- Отказ, который CLI даёт до вызова инструмента (неизвестный флаг, нет
  обязательного аргумента, неверный тип в `--arg`), в журнал не попадает:
  CLI проверяет аргументы сам, до вопроса о согласии. Тот же отказ по MCP
  записывается. Записывается каждый вызов, который дошёл до инструмента.
- Локальные команды (`evo configure`, `evo init`, `evo verify` и др.,
  список — в [commands.md](commands.md)) инструментов не вызывают и в журнал
  не пишутся.
- Запись, которую не удалось сделать (диск, права, журнал занят другим
  процессом дольше 0,1 с — например, идёт `evo diag export`), теряется;
  ответ вызова журнал не задерживает дольше этого и не меняет.
- Превью платного или разрушительного вызова записывается с `error: true` и
  `preview: true`: ответ `confirmation_required` в MCP — `isError: true` по
  замыслу (DECISIONS D9), журнал пишет его как есть. Отличает превью от
  ошибки поле `preview`.
- Вызов инструмента вне `--toolsets` сервера (и неизвестного инструмента)
  отклоняется протоколом — ошибкой `-32602` до инструмента — и в журнал не
  попадает.
- Предел файла — 16 МБ минус 512 байт: этот остаток держится под последнюю
  запись `journal_full`, после неё журнал не пишется.
