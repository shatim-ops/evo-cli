### Миграция

- **Долгий вызов MCP отвечает не позже ~45 с, отмена — `INTERRUPTED`** (DECISIONS D69; агентные прогоны 1.6.0: клиенты MCP обрывают вызов через 60 с).
  Было: `deploy_apply` по MCP ждал ВМ до 25 мин в одном вызове, клиент обрывал его, и агент не знал, что ВМ создаётся; `*_operation` принимали `wait_seconds` до 300; отменённый вызов отвечал `API_UNREACHABLE` с подсказкой «проверьте сеть» (у `provision` — `VM_PROVISION_FAILED`), отменённый `deploy_apply` не называл ни ВМ, ни пароль.
  Стало:
  - `deploy_apply`, который не дождался ВМ за ~45 с, отвечает **не ошибкой**: `status: creating`, `vm_id`, `vm_status`, `plan_id`, пароль ВМ (один раз) и следующий шаг — `next` текстом, `next_tool`/`next_args` для агента. Повтор того же вызова с тем же `plan_id` подхватывает ВМ и доделывает её. Аргумент `wait` (`evo deploy apply --wait=false`): `false` — ответ сразу, как облако приняло создание, `true` — ждать без предела. CLI по умолчанию ждёт, как раньше (строка H14 в `docs/mcp.md`).
  - `wait_seconds` у `ar_operation`, `cert_operation`, `dns_operation`, `kafka_operation`, `lb_operation`, `pg_operation`, `redis_operation`, `vpc_operation` — не больше 45, больше — `USAGE`, код 1, до запроса (было: до 300, больше урезалось); у `stack_status` — не больше 20 (так он и ждал, описание обещало 240). По MCP ожидание кончается с пределом вызова: ответ — состояние операции на сейчас.
  - `dns_zone_delete`, удаление которого не кончилось за предел, отвечает `deleting` с `operation_id` и следующим шагом `dns_operation`.
  - Отменённый вызов (Ctrl-C, отмена клиента MCP, остановка сервера) отвечает `reason: INTERRUPTED` на обеих поверхностях (`evo tools call` — код 130) и называет уже начатое: `provision` — `vm_id`, `deploy_apply` — `vm_id`, `plan_id` и пароль с `note` «пароль только в этом ответе», `dns_zone_delete` — `id`, `visibility`, `operation_id`.
  Что поменять: агент, который ждал от `deploy_apply` по MCP только `running` или ошибку, читает `status: creating` и вызывает `next_tool` с `next_args`; кто хочет ждать в одном вызове — `wait: true` и тайм-аут клиента (`MCP_TOOL_TIMEOUT` у Claude Code). Скрипты, которые ветвились по `API_UNREACHABLE`/`VM_PROVISION_FAILED` при отмене, проверяют `INTERRUPTED`; `wait_seconds` больше 45 — уменьшить. Остальные долгие инструменты (`deploy`, `destroy`, `stack_destroy`, `k8s_kubectl`, `k8s_helm`, `disk_create`, `disk_attach`) получают предел следующими PR 1.7.
