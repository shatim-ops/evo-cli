### Миграция

- **`evo vm create`, `evo tools call provision` и MCP `provision` с образом,
  которого нет в каталоге, или с подсетью не той зоны отказывают до превью и
  вопроса о согласии** (DECISIONS D39; исправление: живой прогон Grok на
  1.3.0, G130-02 и G130-27 — превью с ценой и вопрос, отказ после «да», 3 из
  3 на CLI и MCP). Было: образ по имени или UUID, которого нет, — превью с
  ценой, без `--yes` код 3 (`confirmation_required`), с `--yes` — `NOT_FOUND`,
  код 4 после согласия; имя, под которое подходят несколько образов, — после
  согласия `NOT_FOUND` без списка; `subnet_id` не из проекта или другой зоны
  — превью с зоной из конфигурации, отказ `CONFIG_INVALID`, код 2, после
  согласия. Стало: образа нет — `NOT_FOUND`, код 4, до превью, как обещает
  описание инструмента; несколько — `USAGE`, код 1, с `candidates`, как у
  `image_get`; подсеть не из проекта или не из зоны — `CONFIG_INVALID`, код 2,
  до превью. Облако до отказа только читается. Превью `evo deploy` и MCP
  `deploy` с образом, которого нет, — тот же отказ. Что поменять: скрипт,
  который по коду 3 показывал превью, а `NOT_FOUND` ждал только после
  подтверждения, теперь получает код 4, 1 или 2 на первом же вызове —
  проверяйте `reason` до разбора превью. Ошибка чтения каталога (сеть, 5xx)
  превью не отменяет: тогда образ проверит сам вызов, как раньше.

### Изменено

- Описание инструмента `provision`: «No image or region» вместо «No image or
  zone» — аргумента `zone` у инструмента нет, зона задаётся `region`.
