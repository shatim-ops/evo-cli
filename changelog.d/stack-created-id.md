### Исправлено

- **`stack_destroy` удаляет SNAT-шлюз стека** (G13-14, атака Grok, волна 2).
  Шаг `snat` записывал в `outputs` строку `"ok"` вместо id шлюза: id
  искался только в полях `vm_id`, `id` и `path` ответа, а `snat_create`
  отвечает `nat_gateway.id`. В итоге `stack_destroy` отказывал («id "ok" — не
  id»), платный шлюз оставался, а задание навсегда оставалось в
  `destroy_failed`. Теперь id созданного берётся из одного объявления на
  каждый create (`internal/tools/created.go`). Задание, сохранённое до
  исправления, при `stack_destroy` находит шлюз по имени из манифеста и
  удаляет его. Если шлюза уже нет, задание переходит в `destroyed`.
- В `outputs` стека шаги `secret:N` и `s3:N` называют путь секрета и ключ
  объекта, а не `"ok"`; в `deleted` и `failed` ответа `stack_destroy` они
  называются ключом шага (`secret:0`), а не `secret`. Если синхронный шаг стека не получил id созданного и
  не нашёл ресурс по имени, шаг завершается ошибкой, а не `done`.
