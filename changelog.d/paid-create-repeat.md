### Миграция

- **Повтор платного создания после потерянного ответа спрашивает заново**
  (D107) — `evo pg create`, `evo kafka create`, `evo redis create`,
  `evo k8s create`, `evo k8s add-nodepool`, `evo lb create` и инструменты
  `pg_create`, `kafka_create`, `redis_create`, `k8s_create`,
  `k8s_add_nodepool`, `lb_create`. Было: вызов с согласием, ответ которого не
  пришёл (обрыв связи, 5xx, прерванный вызов), повторялся тем же вызовом — и,
  пока список сервиса ещё не показывал созданное, отправлял второй запрос:
  второй кластер или балансировщик с тем же именем, оплачиваемый с первой
  минуты. Стало: повтор ничего не отправляет и отвечает вопросом
  (`confirmation_required` с полем `interrupted`): первый запрос мог быть
  принят, созданное может ещё не быть в списке, «да» создаст второй платный
  ресурс. В CLI с `--yes`, с `--json` и без терминала — код выхода 3, на
  вопрос отвечает только человек в терминале. Вопроса нет, если список уже
  показывает созданное (повтор отвечает как на занятое имя) и если запрос на
  создание в первом вызове не уходил. Что поменять: после ошибки без ответа
  облака читать список по имени (`evo pg list`, `evo kafka list`,
  `evo redis list`, `evo k8s list`, `evo k8s nodepools`, `evo lb list`) и
  повторять создание только после ответа человека; сценарий, который
  повторял `create --yes` до успеха, остановится на коде 3.

### Исправлено

- **Ответ создания, у которого потерян ответ облака, называет проверку
  чтением**: «до любого повтора проверьте список по имени», а не приглашает
  повторить вызов.

### Известные ограничения

- Правило «повтор после потерянного ответа спрашивает заново» действует для
  шести созданий выше. Для `ar_create`, `cert_import`, `dns_record_create`,
  `pg_backup_create`, `snat_create`, `tg_create`, `vpc_create`,
  `vpc_route_create` повтор после потерянного ответа, пока список не показывает
  созданное, по-прежнему может создать второй ресурс с тем же именем; превью
  evo называет каждый из них платным без известной цены. Ответ на потерянный
  ответ у них теперь говорит проверить список до повтора.
- Запись о создании с потерянным ответом закрывается, когда список показывает
  ресурс с этим именем, — в том числе созданный не этим вызовом; второй
  платный ресурс при этом не создаётся: повтор отвечает, что имя занято.
