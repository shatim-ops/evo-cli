### Добавлено

- **`vm_start` (`evo vm start <vm_id|имя>`) — запуск остановленной ВМ.**
  До вопроса evo читает ВМ и показывает в превью её id, имя, состояние,
  команду (`power_on`) и проект. С согласием шлёт команду и ждёт состояния
  `running`; ход называет состояние ВМ. Повтор безопасен: ВМ уже работает —
  `already_running` без вопроса и без записи; ВМ уже запускается — evo ждёт
  и второй команды не шлёт. На пределе вызова MCP ответ — `status: starting`
  с `next_tool: vm_start`: шаг продолжает свой запуск тем же вызовом, пока
  с начала операции не прошло 5 минут; дальше ответ — состояние ВМ,
  `since_start_sec` и `next_tool: vm_get` — evo её больше не ждёт. ВМ удаляется или не создана — отказ `USAGE` до
  вопроса; ВМ нет — `VM_NOT_FOUND`. Запущенная ВМ платная: превью называет
  класс цены `paid_unpriced` и ссылку на тариф — цена неизвестна, ресурс
  платный.

### Известные ограничения

- `vm_start`: повторный вызов, заставший запуск, который начал не он,
  ждёт один предел вызова и отвечает `status: starting` с
  `next_tool: vm_get` — состояние ВМ дальше показывает чтение, а не повтор. Запуск ВМ из состояния `error`
  не отвергается заранее: превью предупреждает, что исход неизвестен, а
  отказ платформы приходит без шага повтора.
