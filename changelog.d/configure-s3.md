### Добавлено

- **`evo configure s3 --tenant-id <tenant_id>` задаёт ключи S3 профиля из его ключа доступа** (агентный прогон M2 на 1.6.0, Ц-10).
  Object Storage принимает тот же ключ доступа в другом виде: `access_key` — `<tenant_id>:<Key ID>`, `secret_key` — Key Secret. Команда пишет секцию `s3` профиля из сохранённого ключа, секрет второй раз не вводится и в командную строку не попадает; `endpoint` и `region` секции остаются прежними. Без ключа в профиле — `CONFIG_INVALID`, код 2 («сначала `evo configure`»); `tenant_id` с пробелом, `:` или `.` — `USAGE`, код 1. Отказ инструментов `s3_*` без ключей S3 (`CONFIG_INVALID`, код не изменился) теперь в подсказке называет эту команду и где взять tenant ID. В `docs/mcp.md`, в разделе Claude Code, — где задаётся `MCP_TOOL_TIMEOUT` (у клиента, не в `env` сервера).
