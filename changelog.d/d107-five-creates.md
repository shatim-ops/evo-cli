### Миграция

- **Повтор после потерянного ответа спрашивает заново ещё у пяти созданий**
  (D107, решение владельца 13.11) — тем же правилом, что у `evo pg create`
  и других платных созданий: повтор ничего не отправляет и отвечает вопросом
  (`confirmation_required` с полем `interrupted`), пока список не показывает
  созданное; в CLI с `--yes`, с `--json` и без терминала — код выхода 3, на
  вопрос отвечает только человек в терминале. Вопроса нет, если список уже
  показывает ресурс (повтор отвечает как на занятое имя) и если запрос на
  создание в первом вызове не уходил. Что поменять — по строке на каждое:
  - `evo vpc create` / `vpc_create`: после ошибки без ответа облака — `evo vpc
    list` по имени; сценарий, который повторял `vpc create --yes` до успеха,
    остановится на коде 3.
  - `evo tg create` / `tg_create`: проверьте `evo tg list` по имени; повтор
    `tg create --yes` остановится на коде 3.
  - `evo ar create` / `ar_create`: проверьте `evo ar list` по имени; повтор
    `ar create --yes` остановится на коде 3.
  - `evo cert import` / `cert_import`: проверьте `evo cert list` по имени;
    повтор `cert import --yes` остановится на коде 3.
  - `evo pg backup-create` / `pg_backup_create`: проверьте `evo pg backups
    <cluster-id>` по имени — копия ищется в своём кластере; повтор
    `pg backup-create --yes` остановится на коде 3.

### Изменено

- Превью `evo cert import` / `cert_import` называет имя сертификата отдельным
  полем `name`, как превью других созданий: вопрос после оборванного вызова
  называет сертификат по нему.
