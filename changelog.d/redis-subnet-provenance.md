### Миграция

- **Списки кластеров Redis и Kafka.** В 1.9.0 `evo redis list` и `evo kafka list` могли завершиться с кодом 0, если API вернул HTTP 200 с телом `null` вместо страницы. В результате оставались только ранее прочитанные кластеры, а при сбое на первой странице список выглядел пустым. Элемент `null` внутри массива `clusters` также проходил как строка с пустыми полями. Инструменты MCP `redis_list` и `kafka_list` сообщали об успехе.
  В 1.9.1 оба случая означают неполный список: CLI завершается с кодом 5 (`API_ERROR`), MCP возвращает `isError: true` и `reason: API_ERROR` в теле результата инструмента. Корректная последняя страница с `{"clusters":[]}` по-прежнему успешно завершает чтение.
  В скрипте CLI проверяйте код выхода до разбора списка; при коде 5 с `error.reason` равным `API_ERROR` в JSON ошибки остановите действия, зависящие от списка. В клиенте MCP проверяйте `result.isError` перед чтением `clusters`. Возобновляйте такие действия после успешного чтения полного списка.

### Исправлено

- Превью удаления Redis и подсети показывает `created_by_evo: yes`, если журнал этой папки подтверждает создание ресурса с тем же облачным ID в проекте цели. Совпадение имени и старая запись без подтверждения дают `unknown`.
- При асинхронном удалении Redis проверка журнала также учитывает терминальное состояние ERASED, полученное по ID кластера. Если в карточке нет проекта, проверка сверяет ID с полным списком Redis выбранного проекта. При ошибке чтения или исчерпании лимита запросов запись остаётся в журнале.
- В `history --check` страницы списка Redis входят в предел 50 чтений. В тексте и в `checked.read` учитываются только чтения по ID.
