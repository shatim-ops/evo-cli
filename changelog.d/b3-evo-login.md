### Добавлено

- **`evo login` — вход через браузер.** Команда открывает страницу входа Cloud.ru (OpenID Connect с PKCE), затем — страницу согласия evo на этой машине (127.0.0.1): проект, для кого ключ (`--for me` — аккаунт `evo`, `--for agent` — аккаунт `evo-agent`) и срок 7, 30 или 90 дней (`--key-ttl`, по умолчанию 30). Вашими правами evo создаёт или переиспользует сервисный аккаунт, выдаёт ему роль «Администратор проекта» до срока ключа (роль включает удаление ресурсов), создаёт ключ последним и записывает его в профиль. Сбой после записи откатывает созданное этим входом. Прежний ключ, созданный `evo login` для профиля, отзывается. Токены человека остаются в памяти, секрет ключа нигде не показывается. Адрес входа печатается в stderr (с `--json` — строкой JSON).
- **`evo logout`** удаляет ключ, созданный `evo login`, — по его id, его же токеном — затем профиль; сервисный аккаунт и роль остаются. Ключа уже нет — `"key": "already_deleted"`. Профиль с ключом из `evo configure` удаляется один, ключ остаётся в облаке. Без терминала нужен `--yes`.

### Изменено

- Отказ IAM для ключа `evo login`, чей срок прошёл, говорит «ключ доступа истёк <дата>; нужен человек: `evo login` или новый ключ в консоли; повтор не поможет» и несёт `key_expired: true`; `reason` и код выхода прежние (`AUTH_FAILED`, 2).
- `evo agent setup` предупреждает, если ключ профиля создан `evo login`: его роль разрешает удаление ресурсов.
- `evo configure` с другим ключом снимает с профиля сведения прежнего `evo login`, чтобы `evo logout` не удалил чужой ключ.
