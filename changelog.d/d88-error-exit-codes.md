### Миграция

- **Ошибка у `whoami`, `evo agent setup` и MCP `provision` с пустым именем больше не выглядит успехом и не доходит до вопроса** (DECISIONS D88). Что меняется:
  - **`whoami`**. Облако отвергло токен ключа (401) при чтении проектов или ролей. Было: код 0 и «роли неизвестны». Стало: `AUTH_FAILED`, код 2, с подсказкой выпустить новый ключ. Ответ 403 или 5xx по-прежнему не ошибка: ключ работает, а почему ролей не видно, объясняет `roles_note`.
  - **`evo agent setup`**. Система не дала прочитать или записать файл клиента: путь занят файлом, нет прав, диск полон. Было: сырая ошибка, код 1. Стало: `CONFIG_INVALID`, код 2, с путём к файлу и подсказкой `--print`. Если клиент переписал файл, пока вы читали diff, ответ прежний: код 1.
  - **MCP `provision` и `evo tools call provision`**. Аргумент `name` задан, но пуст. Было: превью с ценой и вопрос (`confirmation_required`, у `tools call` — код 3), а с `confirmed` создавалась ВМ с именем по умолчанию. Стало: `USAGE` (код 1) до превью, как у `evo vm create ""`; в облако ничего не уходит. Без `name` имя выбирается по умолчанию, как было.

  Что поменять: скрипт, который считал код 0 у `whoami` успехом входа, теперь получает код 2 на отвергнутом ключе — выпустите новый ключ (`evo login`). Не передавайте пустой `name` у `provision`: либо задайте имя, либо уберите аргумент.
