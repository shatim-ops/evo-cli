### Изменено

- **Описания для ИИ-агента говорят, чьё согласие нужно и где искать превью** (план 1.7, P10; прогоны Grok на 1.6.0).
  - Аргумент `confirmed` у всех изменяющих инструментов MCP описан как «не передавайте — получите превью; true только после того, как человек одобрил это превью». Было «Must be true — set only after the user approved», и модель читала это как «ставь true»: в прогоне с LLM 90 % подтверждённых вызовов шли без превью.
  - Справка `--yes`: это согласие человека, данное заранее; агент сам его не ставит.
  - `evo mcp` без `--toolsets` предупреждает в stderr при запуске (по stdio и по HTTP), сколько инструментов и килобайт схем клиент получает в каждой сессии, и предлагает `--toolsets`.
  - Описания `billing_balance`, `billing_consumption`, `billing_finops` и правила агента (`evo agent skill`): задаче только на чтение человек может запустить сервер с `evo mcp --read-only`.
  - Описание `deploy` называет имя ВМ: `evo-<project_name>` (из `.evo.yaml`, иначе имя каталога); имя задаёт `deploy_plan`, а не `deploy`.
  - Коды выхода, `reason` и поведение инструментов не изменились.
