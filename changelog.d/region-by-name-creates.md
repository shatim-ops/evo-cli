### Миграция

- **Зона из настроек, которой нет в списке зон, — отказ до согласия: `evo disk create`,
  `evo snat create`, `evo image create` и MCP `disk_create`, `snat_create`,
  `image_create`** (DECISIONS — номер выдаёт «1.6 — релиз»; аудит `cli-ids-1.6.md`, P-Z1).
  Было: имя из `CLOUDRU_REGION`/`--region` уходило в облако как `availability_zone_id`; превью и вопрос о согласии (без `--yes` — код 3), отказ платформы — только после «да» (`API_ERROR`, код 5).
  Стало: зона разрешается по имени или UUID, как у ВМ; имени, которого нет, — `USAGE`, код 1, до вопроса, с перечнем зон в подсказке.
  Что поменять: скрипт, который ждал код 3 или 5 от create с опечаткой в зоне настроек, проверяет код 1.

### Исправлено

- **Зона из настроек именем (`CLOUDRU_REGION=ru.AZ-2`, `--region ru.AZ-2`) в
  `evo disk create`, `evo snat create`, `evo image create`.** Было: так
  работали только ВМ и развёртывание, хотя README с 1.2.1 обещал «`--region`
  понимает имя». Стало: существующее имя зоны принимается и уходит в облако её
  UUID. `image_create` определяет зону (заданную, из настроек или диска-источника)
  до вопроса, и превью называет её.
