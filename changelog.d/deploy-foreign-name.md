### Миграция

- **`evo deploy` и MCP `deploy` с именем ВМ, занятым чужой ВМ, отказывают до вопроса о согласии и не советуют её удалить** (DECISIONS D73, дополнение 04.11; аудит Fable 1.7, FB170-2).
  - Было: `deploy` называет новую ВМ `evo-<project_name>`. Если в проекте уже есть ВМ с этим именем, которой нет в state папки, `deploy` всё равно спрашивал согласие: без `--yes` — код 3, превью MCP — `confirmation_required`. После «да» Cloud.ru отвечал 409, ответ — `CONFIG_INVALID`, код 2, с подсказкой удалить ту ВМ (`evo vm delete`), хотя она может быть чужой.
  - Стало: такое имя — отказ до вопроса и уже в превью MCP: `USAGE`, код 1, с `existing_id` той ВМ, ничего не создано, floating IP не резервируется. Подсказка — задать другой `project_name` в `.evo.yaml` или развернуть из каталога с другим именем; удалить ВМ — решение человека. Тот же текст у 409, если ВМ с этим именем появится между превью и созданием. Как у `provision` и `deploy_plan` с 1.7.
  - Что поменять: скрипт, который ждал от `evo deploy` в этом случае код 3 или 2, получает код 1 с `existing_id`; выход — другой `project_name`.
