### Изменено

- **Правило порта помечено id своей ВМ, и удаление ВМ закрывает его из любого каталога.** Правила портов, которые открывают `deploy`, `provision` (`evo vm create --port`) и `deploy_apply`, получают описание `evo: port N (vm <id>)`. Раньше было `evo: port N`, у `deploy_apply` — `auto: <продукт> port N`. `destroy`, `evo vm delete` и MCP `destroy` (с целью и без, шаг ВМ `stack_destroy`) находят правила с меткой удаляемой ВМ во всех группах проекта. Превью называет их до вопроса, а закрываются они после удаления ВМ, даже если в state этого каталога их нет. Ответ (`security_group_rules.closed` и строка CLI) называет каждый закрытый порт с id ВМ из метки, например `8080 (vm <id>)`. Правило, которое держит запись этого каталога (оно нужно другому развёртыванию или ждёт повторного `destroy`), идёт прежним путём. Удаление уже удалённой ВМ, у которой остались такие правила, закрывает их; без них ответ, как и раньше, `already_deleted`.

### Известные ограничения

- Правило, которое открыла ВМ из другого каталога, закрывается вместе с ней, даже если на этот порт полагается ВМ третьего каталога: её `deploy` своего правила не создавал, потому что порт уже был открыт. Превью `destroy` предупреждает, что группа общая; снова открыть порт — `evo deploy --force` в том каталоге. Правила, открытые до 1.7, метки не имеют и по ней не находятся.
