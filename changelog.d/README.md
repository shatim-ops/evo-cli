# Фрагменты CHANGELOG

Запись в CHANGELOG продуктового PR (`CLAUDE.md` §5) — не правка
`CHANGELOG.md`, а свой файл здесь: `changelog.d/<тема>.md`, например
`ar-create-taken-name.md`. У каждого PR свой файл, поэтому PR одной версии не
конфликтуют в разделе «[Не выпущено]», и вливать `main` в ветку можно без
ручного слияния списков.

Формат — разделы `CHANGELOG.md` без заголовка версии:

```markdown
### Миграция

- **`evo ar create` с занятым именем отказывает до согласия** (DECISIONS D…).
  Было: … Стало: … Что поменять: …

### Исправлено

- …
```

- Разделы — `### Миграция`, `### Добавлено`, `### Изменено`, `### Устарело`,
  `### Удалено`, `### Исправлено`, `### Безопасность`, `### Известные
  ограничения`; каждый не больше одного раза и не пустой. «Известные
  ограничения» — то, что версия заведомо не делает (например, «- Пароль ВМ,
  созданной шагом `provision` в стеке, не отдаётся в `stack_status`…»); раздел
  идёт последним.
- Пункт начинается с `- ` в начале строки; продолжение — следующие строки
  до следующего пункта или раздела. Текста вне пунктов нет.
- `### Миграция` во фрагменте делает PR ломающим для CI так же, как раздел в
  `CHANGELOG.md` (класс «ломающее» в summary run).
- Поправить запись, уже влитую в `CHANGELOG.md`, — правкой `CHANGELOG.md`,
  как раньше.

Проверка — `python3 scripts/changelog.py check` (идёт в CI). Перед тегом, rc
или стабильным, релиз вливает фрагменты в «[Не выпущено]» командой
`python3 scripts/changelog.py fold` (`docs/RELEASING.md`, шаг 0): разделы
сливаются в порядке выше, «Миграция» — первой, файлы удаляются.
