### Безопасность

- **`deploy_apply` дописывает на ВМ только те ключи пользователя, которые
  показал план.** `deploy_plan` показывает ключи из
  `.evo/user_authorized_keys`, и человек одобряет их вместе с планом. Раньше
  `deploy_apply` перечитывал файл при применении, и ключ, добавленный после
  одобрения, получал SSH на ВМ. Теперь план хранит хеш показанных ключей.
  Если файл с тех пор изменился, `deploy_apply` отказывает до создания ВМ
  (`CONFIRMATION_REQUIRED`, код 3) и просит заново выполнить `deploy_plan`.
  План без хеша, сохранённый прежней версией, при ключах в файле тоже
  отказывает — его нужно составить заново. Ключи, прошедшие сверку, и есть
  те, что дописываются на ВМ: файл после сверки не перечитывается.

### Миграция

- **План `deploy` прежней версии при ключах пользователя.** Было: план,
  сохранённый до 1.8, применялся, и `deploy_apply` дописывал на ВМ ключи из
  `.evo/user_authorized_keys`, какими они были в момент применения. Стало:
  в таком плане нет хеша показанных ключей, и при ключах в файле
  `deploy_apply` отказывает до создания ВМ (`CONFIRMATION_REQUIRED`, код 3).
  Что поменять: выполнить `deploy_plan` заново и применить новый `plan_id`.
