### Миграция

- **`pg_db_create`, `pg_user_create` и `secret_add_version`: ответ облака 2xx без квитанции — ошибка, а не успех** (D112, решение владельца 17.11, #1999). Затронуты `evo pg db-create`, `evo pg user-create` и `evo secret add-version`. Было: HTTP 200 с пустым объектом или оборванным JSON — `created` или `version_added`, код 0. Стало: `API_ERROR`, код 5, сообщение «создано ли, неизвестно». Подсказка называет чтение до повтора: `evo pg databases <cluster-id>`, `evo pg users <cluster-id>` или `evo secret get <path>`. Второго запроса evo сам не шлёт. Первый повтор того же вызова с согласием, пока исход неизвестен (запись вызова открыта), отвечает вопросом, как повтор платного создания (D107), и ничего не шлёт: `confirmation_required` с полем `interrupted`; в CLI с `--yes`, с `--json` и без терминала — код 3. Дальше поверхности расходятся. По MCP вопрос задаётся один раз: следующий вызов с `confirmed=true` — «да» человека на ещё одно изменение — шлёт запрос. В CLI такой вопрос снимает только человек в терминале: с `--yes`, с `--json` и без терминала команда при каждом запуске отвечает кодом 3 и ничего не шлёт. У базы и пользователя вопрос снимается, когда список кластера показывает имя: повтор отвечает как на занятое имя. У версии секрета ответ даёт человек — каждая версия — новое изменение. Что поменять: скрипт, который считал код 0 успехом, на коде 5 с `reason: API_ERROR` читает названный список. Ресурс там есть — создание прошло. Скрипт CLI, который повторяет команду до кода 0, остаётся на коде 3, второго запроса нет: на коде 3 он читает названный список. Клиент MCP, который повторяет вызов с `confirmed=true` до успеха, после вопроса отправит запрос ещё раз — у версии секрета это вторая версия, у базы и пользователя — второй запрос того же имени.

### Исправлено

- **`pg_db_create`, `pg_user_create` и `secret_add_version` не считают успехом ответ без квитанции.** Раньше HTTP 200 с пустым объектом или оборванным JSON давал `created` или `version_added` с кодом 0. Запись вызова закрывалась, и повтор `secret_add_version` добавлял ещё одну версию. Теперь успех — только ответ, который называет созданное: имя базы или пользователя, `version.id` у версии секрета. Без этого ответ — `API_ERROR`: создано ли, неизвестно. Подсказка называет чтение, которое надо сделать до любого повтора, — `pg_databases`, `pg_users` или `secret_get`. Запись вызова остаётся открытой. Превью `pg_db_create` и `pg_user_create` называет имя и кластер полями `name` и `cluster_id` (у базы — и `owner`), а не только в тексте `message`: по ним вопрос после такого ответа сверяется с превью.
