Из-за этого `logs` и `verify` шли по SSH к ВМ, которая ещё загружается, а следующий `deploy` ждал заново. Стало: запись остаётся `provisioned` вместе со своим ожиданием, повтор `deploy` продолжает счёт (D80). **`reason` меняется:** `evo logs`, MCP `logs` и `evo verify` после такой отмены отвечают `DEPLOY_IN_PROGRESS` вместо `SSH_TIMEOUT` — исполнение D76 и «Миграции» 1.7.0 (тот же класс, что исправление 1.7.1 для `deploy`, прерванного бюджетом; решение владельца 05.11). Стало: подсказка добавляет «The local state was not updated (…)»; код выхода и `reason` прежние. Нашёл дельта-аудит 1.7.2 (FB172-6).
