### Миграция

- **`evo disk create`, `evo image create`, `evo dns zone-create`, `evo secret create` и MCP `disk_create`, `image_create`, `dns_zone_create`, `secret_create` с именем (путём секрета), занятым до вызова, отказывают до согласия** (DECISIONS D49).
  Было: диск, образ и зона DNS с занятым именем создавались вторыми (код 0; без `--yes` — код 3), а при потерянном ответе evo мог назвать созданным чужой ресурс с тем же именем; секрет на занятый путь спрашивал согласие, затем падал на отказе платформы (`API_ERROR`, код 5).
  Стало: `USAGE`, код 1, `existing_id` — до вопроса о согласии. Образ проверяется среди собственных образов проекта, образ каталога с тем же именем не мешает; зона DNS — среди зон той же видимости. Превью `image_create`, `dns_zone_create`, `secret_create` читает облако: без ключа или проекта — код 2 (было: код 3).
  Что поменять: два ресурса с одним именем больше не создаются — дайте другое имя или возьмите существующий по `existing_id`; скрипт, который ждал код 3 от превью без ключа, проверяет код 2.

### Исправлено

- Повтор `disk_create`, `image_create`, `dns_zone_create` после обрыва больше не создаёт второй платный ресурс, а потерянный ответ не выдаёт чужой ресурс за созданный (ось 3, «ресурс был до нас»).
