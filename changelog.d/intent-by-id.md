### Изменено

- `evo doctor` сверяет оборванное удаление по id (`pg_delete`, `k8s_delete`, `lb_delete`, `tg_delete`, `vpc_delete`, `cert_delete`) чтением ресурса по id, а не списком проекта профиля. Было: с ключом организации удаление ресурса другого проекта могло быть названо выполненным — в списке проекта профиля его нет, что бы с ним ни случилось. Стало: запись закрывается, только когда чтение по id тем же ключом, которым отправлено удаление, отвечает, что ресурса нет; ресурс ещё есть, чтение не удалось (403, 429, 5xx) или ключ другой — запись остаётся, и `doctor` говорит почему. Статус проверки `pending operation`, `reason` и коды выхода `doctor` прежние.
- Запись прерванного вызова по id (`.evo/intents/`) больше не называет проект профиля: запись уходит туда, где ресурс. Запись называет сервисный аккаунт и замаскированный Key ID ключа вызова.

### Известные ограничения

- Оборванное удаление диска, подсети, floating IP, SNAT-шлюза, образа, кластера Kafka или Redis, зоны или записи DNS `evo doctor` сам не закрывает (в 1.8 закрывал по списку проекта): у evo нет чтения по id, которое отличит удалённый ресурс от ресурса другого проекта. Запись закрывает повтор того же удаления: ресурса нет — `already_deleted`.
