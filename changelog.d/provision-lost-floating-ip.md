### Миграция

- **Внешний адрес ВМ, запрос которого остался без ответа облака, не
  резервируется второй раз** (D107) — `evo vm create` / `provision`,
  `evo deploy` / `deploy`, `evo deploy apply` / `deploy_apply` и повтор
  `evo deploy`, который даёт ВМ недостающий адрес. Было: если ответ на
  создание floating IP терялся (обрыв связи, 5xx, прерванный вызов), а список
  адресов ещё не показывал созданный, тот же вызов резервировал второй адрес;
  до создания ВМ — создавал ВМ без адреса и после загрузки резервировал
  другой. Первый адрес оставался платным и ни к чему не привязанным. Стало:
  запрос создания адреса уходит один раз; повтор в том же вызове — только
  после отказа API (адреса нет). Без ответа evo ищет адрес по точному имени,
  а не найдя — останавливает вызов: до ВМ — «ВМ не создана», после — с id
  ВМ; ответ называет имя адреса, `list_floating_ips` (`evo vpc fips`) для
  проверки и то, что второй адрес не запрашивался. Код выхода и `reason` —
  те же, что у неудачного создания: `API_ERROR` (5), `API_UNREACHABLE` (1),
  при прерывании — `INTERRUPTED` (130); в ответе MCP — поле
  `floating_ip_name`. Отметка об адресе остаётся в state каталога.
  Повтор того же вызова берёт адрес, если список показывает его по имени
  ни к чему не привязанным или на этой ВМ; не показывает — ничего не
  отправляет и отвечает вопросом (`confirmation_required` с полем
  `interrupted`: `floating_ip`, `read_tool: list_floating_ips`, цена адреса
  `floating_ip_monthly_rub`). Отвечает на вопрос человек: по MCP модель
  спрашивает его и с его «да» вызывает инструмент с `confirmed=true`; в CLI
  с `--yes`, с `--json` и без терминала — код выхода 3
  (`CONFIRMATION_REQUIRED`). После «да» резервируется новый адрес, отметка
  первого остаётся. Что поменять: сценарию, который повторял `vm create
  --yes` или `deploy --yes` до успеха, — после такой остановки проверить
  `evo vpc fips` по имени из ответа и повторить; вопрос о втором адресе
  задать человеку.

### Изменено

- `evo destroy` и `destroy` (`vm_id`) освобождают адрес из отметки, если
  список показывает его по имени, и закрывают отметку; не найденный — называют
  в ответе (`lost_floating_ips_not_found`; освобождённые —
  `lost_floating_ips_released`) с тем, где его освободить, если он появится.
  Превью `evo destroy` называет такой адрес строкой. `evo doctor` называет
  каждую отметку предупреждением «lost floating IP».
- Два свободных адреса, оставшихся от прежних запусков `deploy` с тем же
  именем ВМ, больше не выбираются наугад: ни один не берётся.

### Известные ограничения

- Отстаёт ли список адресов Cloud.ru от создания, не проверено прогоном
  (гипотеза); правило не зависит от ответа на этот вопрос.
- Без каталога state (вызов, которому его не дали) отметки нет: адрес
  называет только ответ вызова.
