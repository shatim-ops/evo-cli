### Изменено

- **Превью называет проект, в который уйдёт запись, у каждого изменения по id.** Удаление, изменение и create внутри родителя (`pg_db_create`, `pg_user_create`, `pg_backup_create`, `k8s_add_nodepool`, `k8s_add_addon`, `vpc_route_create`, `disk_resize`, все `*_delete` по id и другие) адресуют ресурс по id и пишут туда, где он находится. Было: превью create внутри родителя называло проект профиля, превью удаления проект не называло вовсе — с ключом организации без `--allow-project` оператор мог подтвердить изменение в чужом проекте. Стало: evo читает проект ресурса до вопроса и называет его (`project_id`, `project_from: resource`); если это не проект вызова — рядом `project_note`; если проект прочитать нельзя — `project_id` нет, `project_note` говорит «не определён», проект профиля не подставляется. В CLI — строки «проект» и «внимание» в `--dry-run` и перед вопросом. `reason`, статус и коды выхода прежние; до вопроса добавился один запрос чтения. Подробнее — `docs/mcp.md`, «Подтверждения».

### Известные ограничения

- Проект диска, подсети, floating IP, SNAT-шлюза, кластера Kafka и Redis и записи DNS evo определяет по списку проекта вызова: ресурс другого проекта получает в превью «проект не определён», а не имя проекта.
