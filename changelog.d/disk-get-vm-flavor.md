### Добавлено

- **`disk_get` (`evo disk get <disk_id>`) — карточка одного диска по id
  одним чтением.** Имя, размер, состояние, тип, зона, `bootable`,
  `encrypted`, `readonly`, `shared`, `serial_id` — как их сообщает
  платформа — и ВМ, к которым диск подключён. Поля, которого нет в ответе
  платформы, нет и в ответе evo: оно названо в `not_checked`, значение не
  подставляется. Только чтение; сервер с `--allow-project` не читает диск
  чужого проекта.
- **`vm_get` (`evo vm get`) называет flavor ВМ:** `flavor_id` и
  `flavor_name` из той же карточки, без нового обращения к облаку.

### Изменено

- **`evo doctor` проверяет прерванный `disk_delete` по id чтением диска
  по id.** Было: запись оставалась открытой с пометкой «у evo нет чтения по
  id» до повтора того же удаления. Стало: ответ «диска нет» тем же ключом,
  которым ушло удаление, закрывает запись; диск ещё есть — запись остаётся
  с его состоянием.
