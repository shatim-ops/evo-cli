# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue: репозиторий открыт, и описание дыры увидят
все раньше исправления.

Пишите через **Security → Report a vulnerability** этого репозитория
(приватный отчёт GitHub). Отчёт видит только владелец.

В отчёте:

- версия (`evo version`) и ОС; CLI или MCP-сервер (stdio, HTTP, Docker-образ);
- что делали и что получили — шаги, команда или вызов инструмента;
- чем это грозит: раскрытие ключа или секрета, действие без согласия,
  обход `--read-only` или `--allow-project`, выполнение чужого кода,
  платный ресурс, который остался без учёта.

Не вставляйте в отчёт настоящие ключи, токены, ID проектов и IP-адреса —
замените их на `<key>`, `<uuid>`, `<ip>`.

## Что считается уязвимостью evo

- бинари `evo` из GitHub Releases, `install.sh`, Docker-образ MCP-сервера;
- политика сервера MCP: согласие на платное и разрушительное,
  `--read-only`, `--allow-project`, ограничения HTTP-режима (H1–H13,
  `docs/mcp.md`), маскирование секретов в ответах;
- цепочка поставки: подписи cosign, закрепление экшенов и образов.

Сбой или дыра самой платформы Cloud.ru — не evo: о ней сообщайте в
поддержку Cloud.ru. Если evo мог бы от неё защитить, но не защищает, —
это наш отчёт.

## Что evo отправляет в сеть

Запросы к API Cloud.ru (`*.cloud.ru`), к адресам из вашей конфигурации
(например, `CLOUDRU_S3_ENDPOINT`), к вашим ВМ по SSH, когда `evo deploy` их
настраивает, и единственное исключение вне Cloud.ru — проверка наличия новой
версии по адресу `https://github.com/cloud-ru/evo-cmcp/releases/latest`
(GitHub, сторонний сервис вне Cloud.ru; подробности ниже). Телеметрии нет:
сведений об использовании, отчётов о сбоях, ключей и идентификаторов проектов
evo не отправляет. Любой новый адрес вне Cloud.ru в коде evo (кроме этого
единственного разрешённого адреса проверки версии) роняет сборку
(`TestOutbound_OnlyCloudRuOrDeclaredLinks`).

Единственный запрос, который evo делает без явной команды человека и вне
Cloud.ru, — проверка актуального стабильного тега релиза: `evo mcp` и
`evo doctor` не чаще раза в 24 часа отправляют один `HEAD`-запрос на
`https://github.com/cloud-ru/evo-cmcp/releases/latest` (без перехода по
редиректу и без скачивания тела, читается только номер тега в заголовке
`Location`). В запросе на GitHub уходят только IP-адрес и заголовок
`User-Agent` с версией evo (без ключей, токенов, cookies и идентификаторов
проектов). Отключить проверку можно переменной окружения
`EVO_NO_UPDATE_CHECK=1` или параметром `update_check: false` в `config.yaml`;
при `CI=true` и в Docker-образе MCP-сервера проверка выключена по умолчанию.

Бинарь evo сам не скачивает программы и не обновляется автоматически; выпуск
с GitHub скачивает `install.sh` или вы.

## Что дальше

Владелец подтверждает получение в рабочие дни. Если ответа нет неделю,
напомните в том же отчёте. Исправление выходит patch-версией; после
выпуска отчёт раскрывается, если автор не против.

## Поддерживаемые версии

Исправления выходят для последней minor-версии. Обновление — той же
командой установки (`README.md`, «Установка»).
