# evo CMCP — CLI и MCP-сервер для Cloud.ru Evolution

**evo CMCP** — командная строка и MCP-сервер для [Cloud.ru Evolution](https://cloud.ru).
Один инструмент управляет облаком и для человека, и для AI-агента:
виртуальные машины, диски, сети и балансировщики, DNS, Managed Kubernetes,
PostgreSQL, Kafka, Redis, Object Storage, секреты и сертификаты, Artifact
Registry и Container Apps — и развёртывает `docker-compose`-проект на ВМ одной
командой. Команда — `evo`. Страницы входа `evo login` в браузере называются
**Evolution CMCP** — это тот же evo.

- **CLI для человека и скриптов**: `evo vm list`, `evo deploy`,
  `evo k8s kubeconfig …`; у каждой команды есть `--json` и
  [стабильные коды выхода](docs/exit-codes.md).
- **MCP-сервер для AI-агентов** (Claude Code, Cursor и др.): `evo mcp` по stdio
  или Streamable HTTP, в том числе в Docker. У каждого инструмента MCP есть
  команда CLI с тем же ответом: `--json` команды — то, что видит агент, кроме
  шести команд из закрытого списка ([mcp.md](docs/mcp.md#ответ-инструмента-и---json-команды)):
  `evo deploy`, `evo destroy`, `evo doctor` и трёх устаревших алиасов.
- **Ничего платного без согласия**: создание ресурсов и удаление данных
  показывают превью с ценой и ждут подтверждения — одинаково у человека и у
  агента.

**CREW edition** — редакция для команд Cloud.ru. Вопросы и ошибки — в
[Issues](https://github.com/shatim-ops/evo-cli/issues/new/choose); уязвимость —
не в Issues, а приватным отчётом: [SECURITY.md](SECURITY.md).

## Возможности (v1.9.0)

При сверке создания по имени `evo doctor` и инструмент MCP `doctor` сохраняют квитанцию, если её владелец или проект не подтверждены. Раньше одноимённый ресурс в списке мог закрыть старую квитанцию. Проверьте ресурс в исходном проекте с соответствующим ключом. Предупреждение означает, что исход операции остаётся неизвестным.

**При переходе на 1.10.0.** При отборе по имени VPC команды `evo vpc subnets`, `evo lb list` и `evo tg list` требуют полный каталог сетей проекта. Если следующая страница повреждена, проверьте код 5 (`API_ERROR`) до обработки результата, в MCP — `result.isError`. При известном UUID сети можно передать его в `--vpc-id`. [Анонс 1.10.0](docs/release-notes/v1.10.0.md).

Если ответ на создание DNS-записи, статического маршрута или шлюза SNAT потерян, проверьте цель в её проекте. Пока исход неизвестен, повтор удерживается в CLI и MCP, в том числе с новым подтверждением. CLI сообщает код 3. Если объект уже виден, ответ содержит его ID. [Порядок восстановления](docs/mcp.md#повтор-сетевого-создания-после-потери-ответа).

При чтении списка ресурсов, прав или расходов проверяйте код выхода до разбора строк (в MCP — `result.isError`). При ответе API с повреждённой страницей или строкой CLI возвращает код 5. Повторите чтение после восстановления сервиса.

**Ресурсы облака.** Виртуальные машины, диски, образы и продукты
маркетплейса; VPC, подсети, группы безопасности и их правила, floating IP,
балансировщики и группы целей, SNAT-шлюзы; публичные и приватные зоны DNS;
Managed Kubernetes с группами узлов, плагинами, `kubectl` и `helm`;
PostgreSQL (базы, пользователи, резервные копии), Kafka и Redis; Object
Storage; Secret Manager и Certificate Manager, в том числе Let's Encrypt;
Artifact Registry и Container Apps. Только чтение — биллинг и FinOps, журнал
аудита, метрики, сервисные аккаунты и квоты.

**Сценарии одной командой.**
- `evo deploy` — `docker-compose`-проект на ВМ: ВМ, публичный адрес, порты,
  Docker и `docker compose up`, проверка (`evo verify`), логи (`evo logs`) и
  удаление (`evo destroy`).
- `evo stack` — набор ресурсов по одному манифесту: план с ценой, применение,
  ход и удаление.

**Эксплуатация.**
- ВМ: запуск, остановка, перезагрузка, смена конфигурации (`evo vm start`,
  `stop`, `reboot`, `resize`), консоль (`evo vm console`) и сводная
  диагностика (`evo vm get --diagnose`).
- Kubernetes: группы узлов — просмотр, масштабирование, удаление; ход
  операций кластера.
- Сеть: правила групп безопасности по одному (`evo vpc sg-rule-create`,
  `sg-rule-delete`), открыть и закрыть порты приложения (`evo vpc open-ports`,
  `close-ports`).
- Резервные копии ВМ и дисков: создание, список, восстановление диска из
  копии, удаление (`evo backup`).
- Журнал изменений `.evo/history/`: что evo менял в облаке, когда и по чьему
  согласию; `evo history --check` показывает, чего уже нет в облаке.

**Ничего платного без согласия.**
- Создание ресурсов и удаление данных сначала показывают превью: проект,
  зону, подсеть, группу безопасности, всё, что evo выбирает сам, и цену — из
  API расчёта Cloud.ru или оценкой по тарифу с пометкой. Без подтверждения
  ничего не создаётся.
- Вызов, который платформа заведомо отвергнет, отказывает до вопроса о
  согласии и называет причину.
- Опасные изменения требуют явного подтверждения: порт «всему интернету» на
  общей группе безопасности, удаление последнего правила SSH к своему
  развёртыванию.

**Надёжность.**
- Повтор безопасен: повторное создание не плодит дублей и не создаёт второй
  платный ресурс после оборванного ответа, повторное удаление уже удалённого
  отвечает `already_deleted`.
- «Создано» и «удалено» значат, что облако это сделало; долгие операции
  называют состояние ресурса и следующий шаг.
- Оборванный вызов не теряется: evo записывает намерение до отправки в облако,
  `evo doctor` называет прерванный вызов.

**Для AI-агентов (MCP).**
- MCP-сервер: более 150 инструментов по stdio или Streamable HTTP, в том числе в Docker; у
  каждого — команда с тем же ответом в `--json`.
- Отбор групп инструментов (`--toolsets`), режим только на чтение
  (`--read-only`), ограничение проектов (`--allow-project`), HTTP с
  аутентификацией и маскированием секретов.
- Значения из облака помечены в ответах как недоверенные (`_untrusted`), а
  отказы не повторяют введённые значения — защита агента от инструкций,
  спрятанных в данных.
- `evo agent setup` подключает сервер к Claude Code, Claude Desktop, Cursor,
  VS Code, Gemini и Codex одной командой и ставит правила для агента.

**Для человека и скриптов.**
- Вход через браузер (`evo login`): ключ выпускается после входа в Cloud.ru,
  отдельные профили для себя и для агента; `evo logout` удаляет ключ.
- `evo whoami` и `evo doctor` проверяют ключ, роли, срок и окружение.
- Ресурсы можно указывать по имени; Tab дополняет имена и id; списки
  фильтруются по зоне, состоянию, имени и другим полям.
- Стабильные коды выхода и `--json` у каждой команды; русский интерфейс,
  английский — с `EVO_LANG=en`.
- Журнал сессии `evo diag` для разбора проблем — без значений аргументов.

Что изменилось от версии к версии и ломающие изменения с инструкцией «было →
стало → что поменять» — в [CHANGELOG.md](CHANGELOG.md); анонс выпуска —
[docs/release-notes/v1.9.0.md](docs/release-notes/v1.9.0.md).

**При переходе на 1.9.1.** Если Redis или Kafka вернули неполную страницу кластеров, `evo redis list` и `evo kafka list` завершаются с кодом 5 (`API_ERROR`). Перед разбором списка проверьте код выхода, в MCP — `result.isError`. [Анонс 1.9.1](docs/release-notes/v1.9.1.md).

### Согласие на размещение балансировщика

Платное размещение балансировщика привязано к проекту, VPC, зоне и подсети. Для прямого вызова MCP запросите `lb_create` без подтверждения, покажите человеку превью и после его согласия передайте `preview_id` с `confirmed: true` в той же сессии. В HTTP сначала выполните `initialize` и передавайте `Mcp-Session-Id`. При изменении размещения покажите новое превью. Первый явный `evo lb create --yes` доступен человеку. Если стек остановился с `awaiting_lb_approval`, сохраните `job_id` и ID готовых ресурсов, запросите `stack_apply` для этого задания и подтвердите фактическое размещение. В MCP верните выданный `preview_id`. Опрос `stack_status` оставляет шаг на паузе.

## Что понадобится

- **Учётная запись Cloud.ru Evolution** и проект, в котором вы администратор:
  evo сам выпустит ключ доступа вашими правами после входа через браузер
  (`evo login`). Ключ, созданный вручную в личном кабинете, тоже подойдёт —
  [docs/auth.md](docs/auth.md).
- Для `evo deploy` — исходящий доступ с вашей машины на порт 22 создаваемой ВМ
  (SSH).
- Для `evo k8s kubectl/apply/helm` — установленные `kubectl` и `helm`
  ([docs/install.md](docs/install.md#kubectl-и-helm)). Остальное работает без
  зависимостей: бинарь статический.

### Быстрее всего — через AI-агента

Если вы работаете с агентом (Claude Code, Claude Desktop, Cursor, VS Code,
Gemini CLI, Codex), скопируйте ему это сообщение:

```text
Установи и настрой evo — консольную утилиту и MCP-сервер Cloud.ru Evolution — по инструкции https://github.com/shatim-ops/evo-cli/blob/main/docs/agent-setup.md. Проверь установку, запусти вход в Cloud.ru через браузер и подключи evo к себе как MCP-сервер. Доступ я выдам сам на странице входа; ключи и секреты у меня не спрашивай.
```

Агент поставит evo, запустит `evo login` и подключит evo к себе. От вас —
войти в Cloud.ru в браузере, выбрать проект и нажать «Выдать доступ»: агент
не может нажать эту кнопку за вас, а секрет ключа не проходит через чат.
Вход через браузер работает, когда агент и браузер — на одной машине;
подробности — [docs/agent-setup.md](docs/agent-setup.md).

## Установка

Linux и macOS:

```sh
curl -fsSL https://raw.githubusercontent.com/shatim-ops/evo-cli/main/install.sh | sh
evo version
```

Скрипт ставит последний стабильный релиз, проверяет sha256 архива и, если
установлен `cosign`, подпись релиза, и кладёт бинарь в `~/.local/bin` (под
root — в `/usr/local/bin`). Конкретная версия —
`CLOUDRU_VM_VERSION=v1.6.0` перед `sh` (см. [install.md](docs/install.md)).

Windows: скачайте `evo_<версия>_windows_amd64.zip` (или `arm64`) из
[Releases](https://github.com/shatim-ops/evo-cli/releases), распакуйте `evo.exe`
в каталог из `PATH` — пошагово с проверкой sha256 в
[docs/install.md](docs/install.md#windows). Там же ручная установка, проверка
подписи, Gatekeeper (macOS) и SmartScreen (Windows).

## Обновление

**CLI.** Linux и macOS — тот же запуск `install.sh`: он заменит бинарь на
последний стабильный релиз. Windows — замените `evo.exe` новым из
[Releases](https://github.com/shatim-ops/evo-cli/releases). Проверка:

```sh
evo version
```

Профиль (`evo configure`) и ключ при обновлении сохраняются. Перед обновлением
на следующую минорную версию прочитайте раздел «Миграция» её
[CHANGELOG](CHANGELOG.md).

**Локальный агент (Claude Code, Cursor и др.).** Клиент запускает `evo mcp` из
`PATH`, поэтому новый бинарь он подхватит при следующем запуске сервера:
начните новую сессию агента (в Claude Code — или переподключите сервер в
`/mcp`). Правила для агента обновите той же командой, что их поставила, — она
кладёт правила текущей версии evo:

```sh
evo agent setup --client claude-code --skill
```

## Быстрый старт

Впервые? Пошаговое руководство — [docs/guide.md](docs/guide.md).

Вход — через браузер: `evo login` выпустит ключ вашими правами в выбранном
проекте. Если ключ уже есть — `evo configure`
([docs/auth.md](docs/auth.md)).

Строки, которые начинаются с `#`, — пояснения к командам. В zsh (оболочка по
умолчанию на macOS) скопированный комментарий без настройки даёт ошибку
«command not found: #»: включите комментарии один раз —
`echo 'setopt interactivecomments' >> ~/.zshrc && source ~/.zshrc` — или
копируйте только сами команды.

```sh
# вход в Cloud.ru через браузер: проект и ключ → профиль "default"
evo login
# ключ принят IAM, какой проект выбран
evo whoami
# конфиг, права файлов, доступность API
evo doctor
# ВМ проекта
evo vm list

# каталог с docker-compose.yml
cd my-app
# .evo.yaml: зона и образ из API
evo init
# что будет создано и сколько стоит; ничего не создаёт
evo deploy --dry-run
# ВМ + публичный IP + docker compose up -d
evo deploy
# порты приложения отвечают
evo verify
# логи контейнеров
evo logs -f
# удалить ВМ и освободить IP
evo destroy
```

Зону лучше выбрать явно (`evo vm zones` показывает, какие открыты для новых
ресурсов): подробности и другие известные ограничения — в
[docs/troubleshooting.md](docs/troubleshooting.md).

## Подключить к AI-агенту

Быстрее всего — одной вставкой: скажите агенту «Настрой evo по
https://github.com/shatim-ops/evo-cli/blob/main/docs/agent-setup.md». Он
проверит evo, запустит `evo login` и подключит evo к себе; доступ в
браузере выдаёте вы ([docs/agent-setup.md](docs/agent-setup.md)).

После `evo configure` агент получает те же возможности через MCP. Проще всего —
одной командой: она дополняет файл настроек клиента (другие серверы остаются),
перед записью показывает diff и спрашивает согласие:

```sh
evo agent setup --client claude-code          # claude-desktop, cursor, vscode, gemini, codex; gigaagent — печать
evo agent setup --client claude-code --skill  # и правила для агента (docs/agent-skill.md)
```

Вручную — Claude Code:

```sh
claude mcp add --transport stdio --scope project evo -- evo mcp
```

Cursor — `~/.cursor/mcp.json` (или `.cursor/mcp.json` в проекте):

```json
{ "mcpServers": { "evo": { "command": "evo", "args": ["mcp"] } } }
```

Агент не создаёт и не удаляет ничего платного без вашего согласия: изменяющий
инструмент сначала возвращает превью с ценой и ждёт подтверждения человека.
HTTP-режим, Docker-образ, отбор групп инструментов (`--toolsets`), ограничение
проектов (`--allow-project`) и режим только на чтение для агента без
присмотра (`--read-only`) — [docs/mcp.md](docs/mcp.md); полный список
инструментов (их более 150) — в [docs/tools.md](docs/tools.md).

|---|---|
| `vm`, `disk`, `vpc` | ВМ (в том числе запуск, остановка, перезагрузка, смена конфигурации, консоль), диски, сети, подсети, группы безопасности и их правила, порты (`vpc open-ports`), floating IP |
| `backup` | резервные копии ВМ и дисков: создание, список, восстановление диска, удаление |
| `history` | журнал изменений evo в облаке и проверка, что из этого ещё есть |

| `marketplace` | витрина: ОС, продукты маркетплейса и плагины Kubernetes одним списком, с командой развёртывания каждого (только чтение) |

| `pg`, `kafka`, `redis` | кластеры PostgreSQL (базы, пользователи, бэкапы), Kafka и Redis |
| `s3` | бакеты и объекты Object Storage |
| `secret`, `cert` | Secret Manager; TLS-сертификаты Certificate Manager, в том числе Let's Encrypt |
| `dns`, `lb`, `tg`, `snat` | зоны и записи DNS, балансировщики нагрузки и их группы целей, SNAT-шлюзы |
| `ar`, `ca` | реестры Artifact Registry; приложения Container Apps |
| `stack` | стек ресурсов по одному манифесту: план с ценой, применение, ход, удаление |
| `billing`, `audit`, `metrics`, `iam`, `org` | баланс, потребление и FinOps; журнал аудита; метрики мониторинга; сервисные аккаунты; квоты (только чтение) |
| `tools list` / `describe` / `call` | любой инструмент MCP-сервера (их более 150) по имени, с аргументами `--arg` |
| `deploy`, `status`, `logs`, `verify`, `destroy` | сценарий «compose → ВМ» |
| `configure`, `whoami`, `doctor` | профили, проверка ключа и окружения |

## Язык

CLI говорит по-русски: справка, ход выполнения, превью, ошибки и подсказки.
По-английски — с переменной `EVO_LANG=en`:

```sh
EVO_LANG=en evo deploy --help
```

Команды, флаги, коды ошибок (`AUTH_FAILED`), коды выхода и ключи JSON — одни и
те же в обоих языках; в JSON-ошибке символьный код — в поле `reason`.
MCP-сервер (`evo mcp`) всегда отвечает по-английски: описания инструментов и
ответы читает агент. Справка команд и флагов всех деревьев (`vm`, `disk`,
`image`, `vpc`, `k8s`, `pg`, `s3`, `secret` и другие) и описания всех
инструментов в `evo tools list` и `evo tools describe` — по-русски; с
`EVO_LANG=en` — те же английские описания, что видит агент.

## Поддержка

Ошибки, идеи, неудобства и вопросы — в
[Issues](https://github.com/shatim-ops/evo-cli/issues/new/choose) этого
репозитория, по форме. Приложите `evo version` и `evo doctor` — подробнее в
[docs/troubleshooting.md](docs/troubleshooting.md#обращение-в-поддержку).
Репозиторий публичный: в выводе замените ID проектов и ресурсов, IP, Key ID и
имена ресурсов на `<uuid>`, `<ip>`, `<имя>`; ключи не вставляйте никогда.

## Сборка из исходников

```sh
go build -o bin/evo ./cmd/evo
gofmt -l . && go vet ./... && go test -race ./... && govulncheck ./...
```

Нужен Go из `go.mod`. `GORACE=atexit_sleep_ms=0` ускоряет `go test -race`
в несколько раз: без неё race-рантайм ждёт секунду на выходе каждого пакета.
CI гоняет то же на Linux, macOS и Windows
(`.github/workflows/ci.yml`). После изменения команд, флагов или инструментов
обновите справку: `go test ./internal/cli -run 'TestCommandsDoc|TestToolsDoc|TestAgentSkillDoc|TestParityInventory' -update-docs`
(`docs/commands.md`, `docs/tools.md`, правила для агента `docs/agent-skill.md` и инвентаризация паритета CLI ↔ MCP
генерируются, CI проверяет, что они актуальны).
