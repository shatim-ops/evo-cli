# Сценарные скиллы evo

Пять скиллов для ИИ-агентов (Claude Code, Cursor, Codex, Gemini CLI и
других) в формате [Agent Skills](https://agentskills.io/specification): по
одному каталогу с `SKILL.md`. Скилл ведёт агента по сценарию на Cloud.ru
Evolution через evo — по шагам, с остановкой на согласие человека перед
каждым платным или разрушительным действием.

| Скилл | Сценарий |
|---|---|
| `evo-scenarios` | с чего начать: какой скилл и какие группы инструментов (`--toolsets`) нужны, путаница имён, долгие операции, ответы на удаление |
| `evo-deploy` | docker-compose-проект на ВМ: превью, развёртывание, статус, логи, обновление, удаление |
| `evo-vm` | ВМ с публичным адресом, открыть и закрыть порт, floating IP, удалить ВМ |
| `evo-postgres` | Managed PostgreSQL подешевле, пользователь и база, строка подключения без пароля, удаление |
| `evo-cleanup` | найти созданное по префиксу имени, удалить в порядке зависимостей, отчёт о том, что осталось и сколько стоит |

Скиллы написаны под evo 1.3 и по-английски: их читает агент.

## Чем отличаются от встроенного скилла `evo`

Встроенный скилл (`evo agent skill`, `evo agent setup --client <клиент>
--skill`, текст — [docs/agent-skill.md](../docs/agent-skill.md)) — правила
работы с evo: `--json`, согласие, превью, ошибки. Он генерируется из
бинаря и всегда совпадает с ним. Сценарные скиллы его не заменяют и не
повторяют: они ссылаются на его правила и добавляют порядок шагов
сценария, точки остановки, ожидание и уборку. Ставьте оба.

## Установка

Ставьте только с тега официального репозитория, той же версии, что ваш
evo: скилл — текст, который агент исполняет. Подписи набора пока нет. Не
ставьте с `main` (он может быть новее бинаря) и из других источников.

**Попросите агента** (Claude Code, Cursor, Codex, Gemini CLI — агент с
доступом к терминалу и установленным evo). Вставьте в его чат:

```text
Установи сценарные скиллы evo из официального репозитория.

1. Выполни `evo version --json` и возьми поле `version`, например 1.3.1.
   Нет evo или версия не вида X.Y.Z — остановись и скажи мне.
2. Склонируй тег этой версии во временный каталог:
   git clone --branch v<version> --depth 1 https://github.com/shatim-ops/evo-cli <временный каталог>
   Только этот тег: не `main`, не форк, не другой источник. Тега нет —
   остановись и скажи мне.
3. Скопируй каталоги skills/evo-* из клона в каталог скиллов своего агента
   для пользователя: у Claude Code это ~/.claude/skills/, у других — по их
   документации. Каталог evo-* там уже есть — скажи, что заменишь, и спроси.
4. Встроенный скилл и MCP-сервер evo: выполни
   `evo agent setup --client <клиент> --scope user --skill --toolsets deploy,vm,vpc,disk,image,pg,auth --dry-run`
   (клиент: claude-code, cursor, codex, gemini) и покажи мне diff. После
   моего «да» — та же команда с `--yes` вместо `--dry-run`. Отказ — покажи
   его текст и спроси: нет ключа (код 2) — ключ ввожу я сам командой
   `evo configure`; у клиента нет правил уровня user (Cursor) — без
   `--scope user`, в каталоге проекта; запись evo в файле другая —
   с `--force`.
5. Проверь: metadata.evo-version в каждом SKILL.md равен major.minor из
   шага 1. Выведи список каталога скиллов. Удали временный клон.
6. Скажи мне начать новую сессию: скиллы читаются при её старте.
```

Затем откройте новую сессию и спросите «какие evo-скиллы ты видишь?». В
ответе — пять `evo-*` и встроенный `evo`. Нет какого-то — каталог не тот,
что читает агент.

Группы `--toolsets` в промпте — для `evo-deploy`, `evo-vm` и
`evo-postgres`; `evo-cleanup` нужны все (`--toolsets all`), об этом говорит
`evo-scenarios`.

**Копированием с тега** (вручную; `v1.3.0` замените на версию из
`evo version`):

```sh
git clone --branch v1.3.0 --depth 1 https://github.com/shatim-ops/evo-cli /tmp/evo-cli
cp -r /tmp/evo-cli/skills/evo-* <каталог скиллов агента>/
evo agent setup --client claude-code --scope user --skill --dry-run
```

| Агент | В проекте | Для пользователя |
|---|---|---|
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Cursor | `.agents/skills/` (или `.cursor/skills/`) | `~/.cursor/skills/` |
| Codex | `.agents/skills/` | `~/.agents/skills/` |
| Gemini CLI | `.agents/skills/` | `~/.gemini/skills/` |

Другие агенты — по их документации о каталоге скиллов.

**Установщиком `skills`** (Node.js), по одному скиллу с тега:

```sh
npx skills add https://github.com/shatim-ops/evo-cli/tree/v1.3.0/skills/evo-scenarios
npx skills add https://github.com/shatim-ops/evo-cli/tree/v1.3.0/skills/evo-deploy
```

и так же `evo-vm`, `evo-postgres`, `evo-cleanup`. Установщик спрашивает,
для каких агентов ставить: **отметьте своего**. Скилл ложится только к
отмеченным: 24.10 (`skills@1.7.4`, тег `v1.3.0`) набор встал для 14 агентов
в `~/.agents/skills/`, а Claude Code, не отмеченный, читает
`~/.claude/skills/` и скиллов не видел. Команда
`npx skills add shatim-ops/evo-cli` без пути ставит набор с `main`, который
может быть новее вашего бинаря. Встроенный скилл установщик не ставит:
`evo agent setup --client <клиент> --skill`.

**Чат Claude Desktop и claude.ai** (скилл загружается в настройках
приложения, evo подключён MCP-сервером) — не проверено: шагов для них пока
нет.

## Проверка версии

`evo version --json`, поле `version`: его major.minor должен совпадать с
`metadata.evo-version` в `SKILL.md`. Скилл `evo-scenarios` проверяет это
первым шагом и при расхождении предупреждает.

## Удаление

Удалите каталоги `evo-*` из каталога скиллов агента. Встроенный скилл
`evo` от этого не меняется.
